# 分開 Log 儀器就緒、ATE 實際測試活動與結果交付

**Status: accepted — 2026-10-19（需求決策已確認；產品實作及配對驗收尚未完成）**

上位機掌握物料、條碼與治具，Log Solution 只負責本輪來源收集與結果；為避免 ATE 尚未開始卻被誤認為已開測，也避免新 Log 在來源準備期間被納入舊檔基準，選擇區分準備中、監控就緒及可信測試活動。READY 表示可接受新輪，BUSY 包含準備中、監控與待確認；開始請求接受後立即鎖定，只有來源基準完成、橋接可靠觀察到監控就緒，才允許上位機啟動 ATE。

監控就緒或 HID 操作成功不能證明 ATE 已開始，測試開始確認須依本輪可信通道活動或有效測試結果；結果可直接出現，不要求先觀察 TESTING。異常／待確認要阻擋開測及交付；啟動失敗由人員排除、確認並復位，不自動重試。狀態標記與結果色帶分別表達儀器狀態與產品結果，避免讓某格顏色同時承擔整輪控制語意。

這項決定接受兩專案同步修改及配對部署的成本，保留 Python／Tk 與 ADR 0005 的既有分工；補充 ADR 0001 的時間語意：Log 監控開始不等同實際測試開始，單工站整輪與中途不換料的決策不變。具體狀態編碼、期限、前景行為與跨專案交接見 [本輪討論定稿](../refactoring/LOG_INSTRUMENT_DISCUSSION_2026-10-19.md)。
