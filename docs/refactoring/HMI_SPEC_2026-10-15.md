# HMI：固定雙語布局、圖示工具列與淺色外觀規格 — 2026-10-15

狀態：需求與測試入口已確認；ready-for-agent。

追蹤議題：[GitHub #47](https://github.com/Bowei1121/B518_205_207_ATE/issues/47)。

## Problem Statement

主頁同時呈現品牌、機型監控標題、狀態與多個操作，有限寬度內資訊重複。繁中與英文長度不同，可能讓控制元件移位，影響操作熟悉度與說明書截圖的一致性。一般唯讀文字與主背景不同，整體外觀不一致；部分視窗標題仍帶專案名稱，無助辨識功能。

這次目標是讓操作位置穩定、圖示容易辨識、外觀一致，保留監控及人工確認流程。主頁同時承擔KVM影像辨識，因此不能只依美觀搬動機器讀取格位、標記或顏色。

## Solution

主頁維持376px固定寬。第一排左側為設定圖示與Foxlink Logo，右側依序為待確認圖示及事項數、整輪警報圖示、語言圖示與下拉選單；採純圖示、固定格位及目前語言提示。保留專案／機型選擇，刪除重複機型監控標題及B518 LOG替代小字。

採已選定的「操作區顯示狀態」配置，監控文字放在開始／停止附近。主標題顯示專案、機型與版本；設定標題簡化，其餘視窗按功能命名。所有App自有視窗固定淺色、預留雙語文字空間，唯讀文字同背景加細黑框，結果色與KVM契約保留。

## Implementation Decisions

1. **範圍與分工**：保留Tk及既有輪次／配置分工，修改桌面呈現、樣式、標題與圖示資產載入；不新增平行監控狀態、衝突計數或語言偏好。高層App操作與既有輪次快照仍是行為入口。
2. **主頁寬度與頂列**：維持376px。第一排左群為設定、Logo，右群為待確認、整輪警報、語言；中間留白。使用固定格位／預留尺寸，文字翻譯、數字位數、停用狀態與Logo缺失不改變排列。具體間距與圖示尺寸依真Tk及既有KVM位置確認，不直接照抄HTML原型像素。
3. **純圖示與可操作性**：設定齒輪、待確認警告、整輪警報鈴鐺、語言地球及下拉提示。主頁不加可見Settings／Review／Language短字；圖示仍有目前語言停留／焦點提示、可辨識操作名稱及鍵盤入口。圖形不依賴各系統彩色emoji恰好渲染一致，採適合Tk的穩定素材或等效繪製方式；不引入另一個UI框架。
4. **Logo與失敗**：使用已提供的137×35藍色Foxlink PNG，保持比例與品牌原圖，不拉伸、裁掉或重新拼字。顯示縮放不改來源檔。載入失敗保留同尺寸空位、不顯示B518 LOG或其他替代品牌字、不移動按鈕；可留診斷，不彈阻塞提示。確認來源與既有打包資產流程，不因圖片已提交就宣稱正式bundle已驗收。
5. **待確認與警報**：數字取目前輪次既有待確認事項清單長度，不按位置去重、不把整輪逾時或保存失敗混入。沿用零筆停用、存在事項才可裁決等行為。數字預留合法狀態所需空間，不以截斷隱藏事項；不同位數均須測試。整輪警報仍獨立確認，不新增聲音、不自動確認或取消。
6. **語言選單**：沿用目前支援語言、母語名稱、目前選取標記與持久偏好。按地球開啟menu，保留鍵盤展開、選取與Escape關閉能力。監控及待確認期間仍可切語言，關閉保存期間沿用既有暫停切換規則；不因換圖示而重啟監控。
7. **移除重複資訊**：移除B518 LOG fallback及機型Log Monitoring標題，保留配置選擇欄與真正功能入口。公司Logo不是要刪除的品牌小字；無額外獨立設備名稱欄位。不可藉移除重複標題刪掉監控狀態。
8. **操作區狀態**：依使用者選定配置，狀態文字位於開始／停止附近的固定欄位。待命、監控中、待確認、關閉保存等適用狀態與必要數量仍由既有狀態表述產生，不只用顏色。配置區不再複製同一狀態；位置調整不改啟動／停止規則或快捷鍵。
9. **主標題**：以目前專案、機型、固定產品名稱ATE Log Solution及集中版本組成，例如「B518 FCT ATE Log Solution-V0.1.0」。機型指DFU／FCT／BT等工站類型，不是受測產品型號。版本集中單一來源，這次不決定遞增版本號；切配置更新、切語言不覆回舊固定標題。配置錯誤沿原處理，不捏造有效設備識別。
10. **子視窗標題**：設定為繁中「設定」／英文「Setting」。歷史、衝突、警報、診斷、保存與一般App提示按功能與目前語言命名，不加專案名稱。已符合者保留，不為一致性另改警報或錯誤語意；系統原生選檔器仍按既有操作與系統能力處理。
11. **固定雙語布局**：涵蓋主頁、設定各頁、衝突精簡／詳細區、警報、歷史條件／列表／詳細／異常、診斷及保存關閉／重試等App自有畫面。以中英文較大需求預留標籤與按鈕空間，不因翻譯pack自然寬度重新推動相鄰元件；長路徑／原文依既有捲動及選取保留。必要可換行文字須有固定區域，不藉無限增高推動操作。
12. **穩定性的比較條件**：同一視窗尺寸、DPI／字型環境、容量與操作狀態下比較切語言前後位置和尺寸；輸入、候選選取、頁碼、閱讀／捲動與視窗生命週期保持。不同容量合法一／兩排KVM、使用者調整視窗或拖曳分隔，仍沿原有行為，不把固定布局解釋成禁止所有調整。
13. **唯讀／輸入外觀**：一般唯讀文字包括SN、路徑與詳細原文，以主畫面底色加細黑框；可編輯或可選擇欄位保留輸入外觀與白底，唯讀狀態的選單仍是可操作選擇欄，不等同輸出indicator。黑框不覆蓋選取、焦點可辨識性；原始資料內容不因呈現修改。
14. **淺色主題**：所有App自有背景、前景、欄位、按鈕及一般／停用／選取／焦點狀態一致採淺色，不能只改根視窗。系統深色模式不改App自有元件配色，不修改全機外觀。原生標題列、選單及系統選檔器不作未驗證的逐App淺色承諾；不為此更換UI技術。
15. **結果與KVM保護**：結果色、未使用格位黑色、固定定位點、黑白狀態標記、排列與當前容量規則沿用現有版本。人用頂列重排不得藉增加高度平移KVM區。比較相同顯示條件下App內KVM位置與元件幾何，保留現有防遮擋與上位機取用語意；不能只證明色塊相對位置相同就忽略整區已搬動。
16. **原型角色**：已選定「操作區顯示狀態」，另一案只作比較來源；原型保存在獨立分支，不將示意HTML或宿主切換控制合入產品。原型省略／模擬的保存重試、封存、診斷、事件等，仍須在正式App保持可用。原型設定頁只有布局方向，不取代完整設定頁功能。
17. **與查詢優化並行**：本規格不重寫查詢資料管理；若另一規格增加首批／後續準備狀態，HMI只負責對應文字與固定區域。兩份規格共享既有App操作與語言契約，分別驗收，不把另一份全部交付列為無條件阻擋。
18. **交付**：允許逐票遷移，正式操作入口、必要真正Tk／桌面驗證與相關回歸通過可合併，最後作整體畫面對照。工廠上位機／設備驗收另追蹤，不阻擋開發合併；不能因此省略本機KVM契約檢查或宣稱正式部署完成。

以下測試入口已由使用者確認採用。

以真正B518 App操作及既有公開輪次、配置、語言入口為主要seam；比較切語言前後實際元件座標／尺寸、文字可讀性、狀態與原始資料。KVM沿既有辨識contract及真Tk呈現對照。使用隔離App根目錄與真實暫存紀錄，不能動正式配置、歷史或設備。

良好測試驗證人可觀察的文字、位置、焦點、實際操作與既有政策，不只斷言樣式字串／helper被呼叫。先例包括真正Tk語言通知、衝突選取／捲動、關閉保存重試、歷史提示鍵盤及KVM格位／標記解碼測試。原型只作設計來源，不作桌面驗收證據。

### 驗證證據與限制

- 記錄固定程式基準、runtime／Tk版本、視窗尺寸、DPI／字型與容量。元件位置以視窗內穩定參考量測，切語言後等待排版完成再比對；不同環境不混作逐像素一致承諾。
- 每類App自有視窗至少有對應真正Tk行為及中英文畫面證據。除bounds比較，也檢查文字與圖示可閱讀、按鈕可到達；不能只靠圖片相似度掩蓋功能消失。
- 對照一般／停用／焦點／選取，以及監控中、待確認、警報待確認與保存失敗等狀態。對同容量同狀態切語言不移位；業務狀態合法改變不能誤報布局缺陷。
- 系統原生外觀與實體KVM／設備環境另標限制，不透過修改全機主題來實作App固定淺色。本機必要桌面驗證未完成不能冒充已通過，但工廠實機驗收不是逐票合併前提。
- 執行受影響的必要回歸及既有完整套件。HMI不改查詢資料演算法，不因本票默認重跑216萬事件數小時成本流程；如發現相關回歸再做有理由的補驗。未跑案例與大型歷史證據明確分開。
