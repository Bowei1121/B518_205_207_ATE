# 人工衝突彈窗：精簡對照與詳細資訊分區

## Problem Statement

操作員在人工決定結果衝突時，目前需要從同一詳細文字區閱讀原結果、新候選、完整來源路徑、識別及證據。資訊過多且差異不突出，難以快速掌握這次衝突改變了哪些內容，尤其同一位置有多個候選時容易混淆。

操作員需要先看到精簡的原／新對照，再按需要查閱完整證據，同時保留熟悉的左側選單與底部裁決操作。

## Solution

左側維持衝突選單、底部維持保留原結果／採用新結果／關閉。右側分為可拖曳調整的上下區域，初始精簡區約 40%、詳細區約 60%。

右上固定以「項目／原結果／新候選」比較結果、SN、來源時間及來源檔名。不同欄位的原／新兩側值皆用紅色粗體，相同欄位維持一般文字；同名但不同路徑時補簡短目錄提示。右下維持原有完整詳細資訊。兩區使用同一捕捉快照，隨左側選取同步更新。

## User Stories

1. As an 操作員, I want 在衝突彈窗先看到精簡比較, so that 能快速掌握需要裁決的差異。
2. As an 操作員, I want 左側保留原衝突選單, so that 不必重新學習如何選擇待處理項目。
3. As an 操作員, I want 精簡區固定比較結果、SN、來源時間及來源檔名, so that 每個衝突都有一致的閱讀順序。
4. As an 操作員, I want 原結果與新候選並列顯示, so that 不必在長篇文字中來回尋找。
5. As an 操作員, I want 看見所選顯示位置, so that 能確認目前處理哪一片產品的衝突。
6. As an 操作員, I want 不同值的兩側都用紅色粗體, so that 可以直接對照變更前後的值。
7. As an 操作員, I want 相同值維持一般文字, so that 不會把全部資料都誤認為差異。
8. As an 操作員, I want 即使無法分辨顏色仍可由粗體辨識差異, so that 差異提示不只依賴顏色。
9. As an 操作員, I want 平常只看見來源檔名, so that 長路徑不會淹沒重要資訊。
10. As an 操作員, I want 同名但不同路徑時補上簡短目錄提示, so that 不會把不同來源誤認為同一檔案。
11. As an 操作員, I want 不同檔名直接標示差異, so that 能辨識兩份來源。
12. As an 操作員, I want 缺少來源或欄位時顯示未知, so that 不會把推測資料當成真實證據。
13. As an 操作員, I want 相同來源檔案的更新仍能突出結果或 SN 的差異, so that 不會因檔名相同而漏看衝突。
14. As an 操作員, I want 來源時間保留平台提供的含義, so that 不會把它誤認為統一的測試結束時間。
15. As an 操作員, I want 右下保留完整詳細內容, so that 需要時能查閱輪次、衝突與來源證據。
16. As an 工程師, I want 完整路徑與原來源識別仍可查閱, so that 精簡顯示不損失排查資訊。
17. As an 操作員, I want 可拖曳調整上下分區, so that 能按當次需要增加精簡或詳細資訊的空間。
18. As an 操作員, I want 視窗縮至既有最小尺寸仍能操作, so that 比較資訊不會擋住選單或裁決按鈕。
19. As an 操作員, I want 切換左側選取時上下資訊一起更新, so that 不會混用不同候選的資料。
20. As an 操作員, I want 處理某項衝突後顯示剩餘正確項目, so that 可繼續逐項裁決。
21. As an 操作員, I want 沒有候選時清空比較與詳細資訊, so that 不會對殘留內容誤操作。
22. As an 操作員, I want 隱藏後重開仍顯示正確候選, so that 可返回尚未完成的覆核。
23. As an 操作員, I want 持續刷新維持仍有效的選取, so that 新候選加入不會把目前比較突然換掉。
24. As an 操作員, I want 底部既有操作按鈕與逐項裁決行為維持, so that 呈現改善不改變選擇的效果。
25. As an 操作員, I want 彈窗維持非模態且其他位置繼續收集, so that 閱讀比較不影響本輪其餘測試。
26. As an 工程師, I want 上下資訊來自同一捕捉快照, so that 檔案後續更新不會悄悄改變待裁決證據。
27. As an 工程師, I want 未知同輪來源的 FAIL 與禁止人工採用政策維持, so that 精簡區不新增錯誤放行途徑。
28. As an 工程師, I want 人工操作 audit 與 KVM 契約維持, so that 版面改善不破壞重建及上位機整合。

## Implementation Decisions

- 此需求僅改善桌面介面的人工衝突呈現，沿用共同輪次提供的 ConflictSide／衝突捕捉快照，不新增來源解析或裁決規則。已確認討論文件是設計依據，UI 變更可逆，沒有新增 ADR 的必要。
- 左側選單與底部既有按鈕維持原位；右側以可拖曳分隔呈現上方精簡對照、下方原詳細資訊。初始 40%／60% 為約略可用高度比例，不要求像素精確；可調整，不新增跨重啟記憶分隔位置的設定。
- 精簡區固定四項，順序為結果、SN、來源時間、來源檔名；欄標題為項目／原結果／新候選，保留目前所選顯示位置識別。原結果表示已接受的結果，新候選表示捕捉的待裁決值，不宣稱時間先後或必然 PASS 變 FAIL。
- 結果、SN 與來源時間按同一捕捉快照的既有值比較，不用重新解析、補時間或改變平台時間語意。缺少值沿用未知；兩側都缺少該值時顯示相同的未知，一側缺少、另一側有值時標示差異。
- 不同欄位的兩側值皆採紅色粗體，相同欄位一般文字。切換選取必須清除前項的差異樣式再呈現當前內容；不因新候選是 PASS 或 FAIL 改成另一套顏色規則。
- 來源檔名取自捕捉來源路徑的檔案名稱。無來源時顯示未知，不把原來源識別碼當作完整路徑猜測檔名。完整路徑及原來源識別仍在詳細區。
- 檔名不同時標示來源檔名差異；檔名相同但來源路徑不同時，兩側補足以區分的簡短目錄提示並紅色粗體。路徑相同則此欄一般文字，其他欄仍獨立判斷；不得只比較 basename 而漏掉同名不同來源。
- 簡短目錄提示優先呈現必要的相異目錄片段，需能區分兩者，不以相同尾端資料夾造成假一致；完整路徑留在詳細區。長檔名及提示需可閱讀，不擠壓底部裁決操作。
- 詳細區維持既有 formatter 的完整內容，包括輪次及衝突識別、顯示位置、原／新結果、完整來源路徑、來源識別、來源時間與證據，不因精簡區已有欄位而刪除細節。
- 上下區域皆對應同一 conflict_id；選取切換、處理後移除、候選集合刷新、無候選及隱藏後重開時同步更新或清空。沿用原本有效選取保持行為，原選項消失後採既有後續選取方式。
- 不重新讀取來源檔案，不變更 frozen snapshot、候選去重、多候選逐項處理或人工裁決保存流程。保留非模態彈窗、其他位置繼續收集、停止收集與結果放行分離。
- 保留現有視窗預設與最小尺寸的可操作性；若為使新分區可讀而需調整初始呈現，仍須驗證原最小尺寸不遮住必要操作，不擅自提高部署螢幕需求。

## Testing Decisions

- 使用者已確認完整討論文件及其中的真正 Tk 驗收方向。主要測試入口沿用實際 B518LogSolutionApp 與共同輪次公開行為：從受控衝突到彈窗選取、比較、裁決及磁碟結果，避免另造與 UI 不一致的比較入口。
- 良好測試驗證看得到的內容、兩側差異樣式、可拖曳與可操作性、選取同步及裁決後結果；不以私有 helper 被呼叫幾次或特定 widget 層級作為唯一驗收。
- 沿用既有真正 Tk 彈窗尺寸、非阻塞收集、隱藏重開、保留原結果測試，以及共同輪次多候選逐項裁決、暫存來源及 audit 重建案例。資料由受控平台來源與共同輪次捕捉產生，不用重新讀檔改寫待裁決內容。

### 必要驗收案例

1. 四項欄位順序及原結果／新候選標題固定，所選位置可辨識，原詳細內容完整保留。
2. 結果、SN、來源時間各自不同、同時不同及全部相同時，只有不同欄位的兩側值紅色粗體；切換後不殘留前項樣式。
3. 不同來源檔名正常顯示並標示差異；完整路徑及原識別仍能在詳細區查閱。
4. 同名不同目錄、尾端目錄名稱也相同等案例，簡短目錄提示能真正區分來源且兩側標紅，不把 basename 相同當成同源。
5. 相同檔案來源但內容值不同時，來源欄一般文字，結果、SN 或時間的實際差異仍突出。
6. 無來源、缺少 SN、缺少來源時間、一側缺少及兩側缺少均顯示適當未知；不使用觀察時間或 mtime 補造來源時間。
7. 初始上下比例約 40%／60%、分隔可拖曳，原最小視窗尺寸下四欄與底部操作仍可使用，長檔名不遮蔽操作。
8. 同位置多候選及不同位置候選切換時，上下資料對應同一項；刷新保持有效選取，新候選加入不混淆現有內容。
9. 裁決移除選項、全部處理完成及隱藏後重開時，上下內容及差異樣式同步更新或清空，沒有舊值殘留。
10. 衝突捕捉後修改來源檔案，原待裁決比較仍使用捕捉快照；同名來源更新不改寫已捕捉候選。
11. 保留原／採用新／關閉的既有效果維持，非模態彈窗不阻塞其他位置收集；未知同輪來源仍不提供人工採用。
12. 人工操作的 audit 重建、產品結果放行及 KVM 顯示契約回歸通過；現有全套測試通過後才交付。

真正 Tk 驗證須使用可存取桌面圖形工作階段的環境；未執行的必要案例明記待驗，不能以 mock 或文件檢查當成通過。本次規格產生不代表上述新增測試已執行。

## Out of Scope

- 改變來源同輪判定、未知候選 FAIL、候選去重、衝突產生條件、逾時或結果放行政策。
- 新增自動選擇候選、批次裁決、未知候選人工採用或新的裁決按鈕。
- 新增、刪除或改寫 audit 磁碟欄位及產品／KVM 顯示契約。
- 重讀來源檔案以更新既有捕捉快照，或猜測來源時間。
- 更換 Python／Tk、全面重做主畫面、增加新的配置項目或持久保存分隔位置。
- 輪次保存復原、關閉、封存、保存期限，以及其他 P1／P2 效能優化票的實作。
- 本次規格撰寫不包含產品實作、現場部署、正式 bundle 或目標設備驗收。

## Further Notes

- 設計依據為 2026-10-07 已確認的人工衝突彈窗討論，維持 ADR 0004 停止收集與放行分離及 ADR 0006 未知同輪來源處理。
- 來源檔名只是閱讀提示，不取代來源身分或同輪證據。紅色粗體表示原／新欄位存在差異，不表示系統偏好採用哪一側。
- 完整詳細區供進一步查證；精簡區呈現資訊與人工決策不應自行推導新的放行政策。
- 規格與驗收以操作員可觀察結果為準，實作完成後須記錄實際測試及 Git 提交／推送結果。
