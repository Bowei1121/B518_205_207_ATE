| 影像尺寸 | 實際接收影像每小格至少12×12 px；不達標時App狀態與心跳兩組一起放大 |
| 運作狀態 | 待命、準備、監控、待確認、完成、可操作的保存關閉期間皆更新，直到畫面銷毀 |
| 判讀方式 | 心跳區影像差異；不解碼0～15數字 |
| 觀察頻率 | 使用者預期每秒一次；不能把目前程式當成已實作固定1秒 |
| 異常條件 | 連續三張有效、新鮮且可讀的影像，心跳圖案皆相同 |
| 計時位置 | 與監控狀態同一行、分成獨立顯示區；中英文／狀態長短不影響計時位置 |
| 計時語意 | 本輪受理開始至停止收集，包含來源準備，不包含停止後人工確認／補存等待 |
| 計時用途 | 作為本次開始流程已受理的輔助證據；不代替監控就緒、ATE活動或完成交付判斷 |

三張影像是t0、t0+1、t0+2秒，跨度約2秒；不是「基準圖之外再三次相同」，也不是完整3秒。使用者已選三張同圖的規則。

## 辨識流程應保留的區分

1. 先確認傳輸與影格新鮮度。
2. 驗證定位、方向／縮放與狀態、心跳兩區可讀性。兩區相鄰不保證同時可見，仍可能局部遮擋或裁切。
3. 在有效的心跳區上判斷格樣變化，壓縮雜訊不可算有效心跳；不需解碼計數。
4. 三張有效同圖才符合本次心跳異常條件。舊影格、缺圖或遮擋不能冒充連續三張有效觀測。
5. 維持既有監控就緒、實際測試活動與完整交付規則，不增加一定讀到計時變化才可交付的條件。

### 三種觀察結果

| 現象 | 能回報的資訊 |
| --- | --- |
| 無新影格／影格時間停滯 | 傳輸或來源影格新鮮度異常，依現有檢查處理 |
| 新影格存在，但格子看不清楚 | 畫面不可讀／遮擋／定位失敗，不能當成App心跳停止 |
| 新影格且心跳區可讀，但連續三張同圖 | 畫面心跳異常；仍不能單憑此證明App程序已終止 |

請結合現有診斷分類，不把所有心跳異常宣稱為App當機。異常不得直接觸發重新開測、強制採用不確定結果或繞過既有人工復位規則。

### 8秒循環與取樣中斷

相隔8秒整數倍的正常心跳也可能相同。應以持續觀測的有效影像判斷，不能拿長時間中斷前後兩張圖作「連續」比較。回呼數量也不等於不同新影格數量。

以下數值／行為尚未與使用者定案，請在橋接端設計與驗收時明列：最大允許取樣間隔、遇到遮擋／中斷時如何清除觀察序列、心跳恢復後需要多少有效變化、錯誤如何回覆上位機及是否需要人員確認。不要擅自把這些草案寫成使用者已確認的操作政策。

## 計時器可怎麼輔助判讀

- 本次開始後觀察到新輪計時增加，可以補充「開始流程已動起來」的證據。
- PREPARING期間時間已會增加，只有狀態標記進入本次監控就緒才允許啟動ATE。
- 計時增加與HID操作成功都不能證明ATE已實際開測；仍須可信測試活動／有效結果。
- 計時停止可能是監控正常結束；不要當心跳停止。
- 上輪03:25可以留在畫面至新輪受理；看見非零數字不能當本輪開始。開始前驗證失敗會保留上輪時間。
- 新輪受理時歸零；若準備中失敗，會保留該輪最後時間。App重開回00:00，歷史最後耗時另存。
- 快速輪次可能來不及觀察秒數增加；不能因此推翻其他已充分確認的就緒／同輪／完成證據。
- 文字辨識失敗不能猜數值、不能把讀不到時間直接判為產品FAIL或自動重測。

## 配對驗收

正常半秒心跳在每秒觀察下不誤報；心跳凍結三張有效同圖能報錯；PTS繼續前進但App圖案不動也能偵測。另驗證：壓縮雜訊、定位／心跳局部遮擋、最小化／其他視窗覆蓋、8秒循環與取樣中斷、計時固定位置、中英文、準備中計時但不得開測、正常停表且心跳繼續、上輪時間殘留與快速完成。

部署時須核對App與橋接相容版本及回復方式；不要將新格位App交給僅支援舊座標的橋接。部署切換與錯誤恢復政策由橋接工作另行定案。
