## What to build

沿用既有語言通知，先接入主畫面與自有提示視窗，完成登記、解除、個別失敗隔離、非阻擋彙整提示、診斷與重試，讓操作員不重開視窗就能恢復文字更新。其他尚未遷移視窗維持原流程，本票不宣稱全部視窗已遷移。

## Acceptance criteria

- [ ] 先核對最新正式入口及必要基準行為，沿用既有通知機制；不新增通用事件匯流排或每視窗背景執行緒。
- [ ] 主畫面與自有提示接入同一語言刷新契約，Tk 操作在原畫面流程進行；正式入口不因主畫面刷新失敗而停止通知其他已登記接收者。
- [ ] 開啟時依 App 目前語言呈現並只登記一次，關閉／銷毀時解除自身登記；重開及隱藏再顯示使用目前語言，不移除其他接收者。
- [ ] 故意讓已接入的一個或多個視窗更新失敗，其餘接收者繼續，保留原輸入、選取、閱讀與原模態操作效果。
- [ ] 主畫面顯示一則不阻擋操作的彙整提示，附重試文字更新與詳細診斷入口；不連續彈窗，提示本身不得與通知形成失敗遞迴。
- [ ] 手動重試使用最新語言及有效視窗，只刷新文字，不重開視窗、重啟監控或持續自動重試；全部恢復後清除現行提示但保留診斷。
- [ ] 診斷沿用 App 事件同筆雙語與待補存機制，不虛構輪次；故意注入保存故障時不得宣稱已落盤或漏掉待保存資料。
- [ ] 保留語言偏好保存與保存失敗處理，刷新失敗不可誤分類為偏好保存失敗；關閉保存期間禁切語政策不變。
- [ ] 真正 Tk 經語言選單與重試入口驗證正常、失敗、連續切語後重試、關閉重開、模態提示及磁碟診斷；不只驗證 callback 次數。
- [ ] 已遷移接收者只走一條有效刷新路徑；未遷移視窗仍維持原操作，不為本票破壞既有檢查。
