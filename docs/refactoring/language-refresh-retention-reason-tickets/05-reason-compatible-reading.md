## What to build

建立可讀取新舊清理原因的集中表述契約，透過真實摘要與真正 Tk 查閱已知原因、未知外層提示及完整原文；正式清理產生端暫不切換。

## Acceptance criteria

- [ ] 先核對 ledger、清理結果、雙語與回復契約；設計相容擴充而不硬指定版本數字，不丟失 active plans／摘要／恢復進度。
- [ ] 讀取新原因識別、參數、捕捉繁中／英文說明與原始診斷；保持 run／輪次／時間／結果／計數關聯。
- [ ] 驗證欄位與版本，只對可靠辨識的舊原因做相容翻譯；不以含糊文字猜測安全類別。
- [ ] 未知或不適用表述格式使用所選語言外層提示查看詳細資訊，內層完整保留原文／原始資料；缺翻譯按既有英文回退，不顯示內部識別碼。
- [ ] 原因表述 Interface 不承擔刪除判定；時間、路徑、序號、身分與原始診斷保持原值。
- [ ] 以真實暫存 ledger 的新格式受控資料、舊格式與混合資料，由新讀取器重建並經真正 Tk 查看列表／狀態／詳細；不只測記憶體。
- [ ] 閱讀及切語不改既存摘要 bytes、不啟動清理；正常清理與產生端維持原路徑，本票僅提供已驗證的相容能力。
- [ ] 涵蓋輪次、App 事件及封存原因，保留現有行為驗證並記錄本票實際結果。
