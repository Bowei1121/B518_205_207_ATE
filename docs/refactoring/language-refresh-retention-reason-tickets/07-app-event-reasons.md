## What to build

App 事件清理改用同一原因契約，清理結果摘要可用繁中／英文查閱並保留原始診斷；到期、安全及未保存保護維持原行為。

## Acceptance criteria

- [ ] App 事件清理成功、跳過、失敗及狀態原因接入 C1 契約，涵蓋格式／序號／時間／管理路徑／待保存原因。
- [ ] 與既有清理執行同筆保存原因識別、參數、雙語與診斷，既有 deleted／skipped／failed 計數與序號資訊保持一致。
- [ ] 從事件自身時間起算、沿用全域期限；pending、保存或耐久性故障、未知／損壞資料保持保護，不虛構輪次。
- [ ] 保留退休序號、pin 住管理路徑、符號連結與路徑替換防護、原子替換及目錄 fsync；表述改造不改任何刪除資格。
- [ ] 不另建 scheduler／journal，沿用既有背景清理與摘要保存，故障重試保留事件與清理進度。
- [ ] 真實 App journal → 清理 → 原因摘要 → 全新讀取器 → 畫面查閱驗證，兩語與原始診斷保持，不只測物件。
- [ ] 驗證尚未到期、待補存、損壞、越界、符號連結、rename後fsync失敗與重試；原刪除／保留及序號解釋結果不變。
- [ ] 舊摘要不改寫，輪次尚未遷移原因仍相容；相關現有測試保持並記錄實際結果。
