# 歷史查詢結果準備：可靠總數、500筆預載與共用資料回收規格 — 2026-10-15

狀態：需求與測試入口已確認；ready-for-agent。

追蹤議題：[GitHub #46](https://github.com/Bowei1121/B518_205_207_ATE/issues/46)。

## Problem Statement

歷史事件查詢已有日期條件、背景載入、固定結果、分頁及持久索引，但有效索引重用仍須為每次查詢準備整批結果，才開始閱讀。H8合成容量量測中，216萬筆事件有162萬符合區間，有效索引重查中位數485.302秒，快照約3.25GiB；換頁本身約4–101毫秒。這能證明結果準備值得改善，不能證明所有耗時都來自複製，也不是正式設備等待承諾。

使用者實際查詢不頻繁、區間較短，也不會逐頁翻完全部歷史。因此這次是有限範圍改善：優先讓可靠總數與前五頁可讀，降低重複處理及記憶體，不全面重寫、不以每票重跑數小時極端測試作為完成標準。

## Solution

按查詢後，在背景確認來源版本、可靠總筆數及全部頁數，再一起發布最新最多500筆資料（每頁100筆）及該次條件。剩餘內容持續分批背景整理，閱讀目前頁面與詳細內容的需求優先；並非等翻到第六頁才開始處理。

列表記憶體只保留閱讀位置附近最多500筆；需要時從已整理資料載入，原文則可靠保留。重用未變更內容與有效索引，各次查詢維持固定版本。失敗只重試未完成部分；取消、替換或關閉時停止舊工作並回收不再使用的查詢資料。

## Implementation Decisions

1. **範圍與責任**：沿用歷史查詢Module及公開提交、取消、頁面與詳細入口；將可靠總數、首批可讀、背景完成及失敗恢復納入同一查詢生命週期，不讓Tk維護第二套版本／排序規則。既有相容入口若仍有呼叫者，採可驗證的漸進遷移，不能中途改壞既有操作。
2. **前置來源確認**：提交時固定日期與當地時區，沿用新舊事件、來源優先、日期判定、診斷與去重契約。只有成功確認的來源版本可構成可靠結果；不能為了快取首批而略過未檢查來源，再假稱這是全範圍最新500筆。
3. **總數優先**：可靠總筆數及總頁數取得後，才發布首批。以每頁100筆計算總頁數；零筆總頁數為0並保留正常空結果操作，不出現可點的假頁。可先查必要索引／識別資訊，不得將算總數等同複製全部原文。
4. **原子發布**：新條件、固定版本、排序、總數／總頁數與最新最多500筆一次成為有效顯示結果。首批發布前仍是準備中，保留舊結果與其原條件；不發布「結果已可讀但總數仍未知」的早期提案。
5. **分開完成語意**：首批可讀不代表全部批次已備妥。總數為該固定版本的完整正常事件數，後續批次準備狀態獨立呈現；不能把尚未準備的頁面當不存在，也不能因後續讀取故障改寫已確認總數。來源本來有診斷時保留原有不完整警告，所謂可靠總數不代表不可讀來源已被證明無事件。
6. **背景預先處理**：首批後持續以有限批次整理後續內容，不是純粹等使用者翻頁才開始。頁面與詳細需求優先於非必要預先處理；不新增無限制並行工作或持續輪詢磁碟。大量掃描、排序、複製及格式準備不移入Tk執行緒。
7. **頁面載入**：每頁100筆，使用者要求頁面未備妥時保留目前可讀頁面、顯示載入中；取得可靠頁面後才替換。頁面請求、目前顯示頁與選取分別保持對應，過期請求不能移動畫面。滑鼠與鍵盤功能沿用現有操作。
8. **列表快取**：以閱讀位置附近最多500筆正常列表資料為窗口，淘汰遠離頁面並按需重新載入。既有首批相容檢視亦須納入同一列表記憶體預算，不另留一份永久500筆。選取詳細、索引游標、診斷及背景緩衝另列有界成本，不能以列表計數掩蓋全部原始物件常駐。
9. **原文與固定版本**：保留H6／H8已交付的可信內容契約：固定查詢的正常事件原文不因來源刪除／同路徑替換而消失。共用內容需版本隔離，查詢引用不能指向會原地覆寫的資料；不得把來源位置清單當完整替代品。即使尚未選取詳細，也不能悄悄放棄已確定結果的原文可讀性。
10. **內容重用**：未變更且已驗證的事件內容與有效索引可跨重查重用，只為新增／變更來源更新必要資料。避免每次查詢重複搬移同一份完整原文；儲存格式及版本化實作由後續實作決定，不在此要求外部資料庫、特定新框架或新原始保存格式。
11. **回收所有權**：查詢替換、視窗關閉及App退出後，釋放不再引用的查詢資料；共用內容仍有有效引用時不得回收。可重用索引保留，無引用的查詢專用／過時內容可回收。原始來源依正式期限正常清理，不因保留衍生版本而延後；衍生版本亦不得無引用永久累積。
12. **取消與重查**：沿用最新有效世代規則，延伸到總數、首批、後續批次、頁面、詳細、進度與錯誤。首批前取消保留舊結果；首批後取消停止該次後續處理，保留已發布結果並清楚標記未完成，只有明確重試／重查才能再啟動。關閉視窗使相關回傳失效，App保存不等待已失效查詢。
13. **部分失敗與重試**：首批後失敗保留結果、日期、總數、頁面及可讀內容，提供未完成部分的重試；同版本繼續，不重新納入新事件。版本不可恢復時提示重新查詢，不假裝只重試就能恢復。保留現有來源異常原文、索引降級與失敗不快取成功的契約。
14. **重啟及偏好**：App重啟可重用可靠磁碟索引，不恢復上一個查詢視窗／列表記憶體，不新增操作員快取設定。查詢偏好及語言仍沿既有保存機制，不因本次優化新增原始事件。
15. **可量測成本**：分別量測來源確認／索引同步、總數、首批、排序及全部背景完成；首批可讀時間包括所有必要前置工作。記錄內容複製bytes／筆數、持久衍生大小、列表數、峰值記憶體及背景工作。不能只讓「完成」回傳提早，實際點頁面仍等待全批完成。
16. **交付與相容**：本次是H8後增量優化，不追溯改判已完成票。維持監控、裁決、同筆雙語、保存成功才關閉及期限清理；不增加HMI全面改版。可分階段交付，必要功能測試、真正桌面及相關回歸通過可合併，工廠驗收不阻擋。

### 效能證據與測試成本

- 修改前固定基準SHA；前後使用同fixture、日期、來源比例、runtime與追蹤設定。主要情境採固定小／中資料集的單日及近7天，涵蓋少於及超過500筆；這是驗收fixture，不宣稱為現場精確分布。
- 各主要成本情境至少三次短時可重現量測，分報首批可讀與全部完成、複製量、快取數／記憶體及磁碟衍生量；揭露冷暖與tracemalloc開關，不混用已追蹤與未追蹤數字。
- 先分段定位，再驗收正常有效索引重查的首批時間及重複完整內容複製量相較基準下降；列表始終不超過500，總原始內容不得全量常駐，反覆重查／關閉後資源不持續成長。若沒有可重現改善，不以改了類別或提早送callback宣稱完成。
- 首次建立與故障恢復分開報告正確性及成本，若出現退步須釐清並處理；不要求它們與正常重查一樣快，不新增未討論的硬性秒數或RAM上限。
- 小固定集合完整核對一次原檔身分／排序／原文，功能回歸驗證邊界與競態。大型驗收只在最後依具體風險補驗，預先記明資料量、目的與停止條件，不預設每票重跑216萬筆五情境三次及所有全頁hash。未重跑的H8結果只能作歷史基準，不能當本版新證據。
- 必要完整回歸與桌面驗證依影響範圍執行；一般套件不默默啟動數小時極端容量流程。正式產線資料、設備效能另列後續，不作合併阻擋。

## Out of Scope

- 改HMI頂列、主題、標題或控制元件布局；僅必要查詢載入／進度／重試狀態在此範圍。
- 修改日期政策、每頁100筆、事件裁決、監控、原始保存格式或期限清理政策。
- 僅保存來源路徑而放棄清理後固定原文、使用估算頁數、先發布首批後才補總數。
- 自動重開上一個查詢、操作員快取設定、外部資料庫部署、新增平台或語言。
- 以合成216萬事件當現場產量／事件數，或以未訂秒數SLA重判H8未完成。
- 工廠驗收與正式部署完成作為開發票合併前提。
