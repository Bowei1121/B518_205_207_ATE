# 美國工廠部署：即時語言切換與雙語 App 事件紀錄

## Problem Statement

App 將部署至美國工廠，現場操作員與工程師需要英文介面，台灣開發人員仍需要繁體中文。現有文字分散於操作畫面、工程師設定、警報、衝突裁決、保存狀態與錯誤訊息，沒有統一語言切換；只翻譯按鈕不能使全部操作資訊可理解。

現有事件常以單一文字訊息保存或只顯示於記憶體，現場與開發人員難以使用各自熟悉的語言查閱同一次問題。直接換掉文字、重開視窗或重寫歷史紀錄又可能丟失輸入、選取、候選快照或原始證據。

## Solution

首版提供美式英文 English 與繁體中文。主監控頁右上角顯示目前語言的按鈕，點擊展開原生語言名稱的選單，勾選目前項目；點選後立即切換，不另要求套用、重啟或進入工程師設定。首次預設英文，之後記住這台 App 上次語言。

所有 App 自有視窗及可翻譯內容同步更新，保留監控、輸入、選取與人工操作狀態；監控中與待確認時允許切換，關閉保存期間暫停切換。所有 App 事件在同一筆紀錄固定保存繁中與英文、訊息識別、參數及必要原始診斷，供台灣與現場完整查閱；畫面語言不改變硬碟原紀錄。

## User Stories

1. As an 現場操作員, I want 首次開啟 App 即顯示英文, so that 不必先讀懂中文才能操作。
2. As an 台灣工程師, I want 可切換繁體中文, so that 能用熟悉語言設定與排查。
3. As an 操作員, I want 主監控頁右上角直接看到語言入口, so that 不需尋找工程師設定。
4. As an 操作員, I want 按鈕顯示目前語言與展開提示, so that 知道它是語言選單。
5. As an 操作員, I want 選項使用 English／繁體中文及目前項目的勾選, so that 即使目前介面不是我的語言也能辨識。
6. As an 操作員, I want 點選語言立即生效, so that 不需再按套用或重啟。
7. As an 操作員, I want 取消選單或重選目前語言不改操作狀態, so that 不會意外中斷工作。
8. As an 操作員, I want 只看到已支援的語言, so that 不會選到未完成翻譯。
9. As an 操作員, I want 語言選單可用鍵盤操作, so that 不完全依賴滑鼠。
10. As an 操作員, I want App 記住上次語言, so that 每次啟動不必重新選擇。
11. As an 工程師, I want 語言設定不綁單一測試配置, so that 換專案或機型不會突然換語言。
12. As an 工程師, I want 配置儲存及匯入匯出不抹除語言設定, so that 選擇能可靠維持。
13. As an 操作員, I want 語言設定保存失敗可見, so that 不會誤以為下次啟動已會遵照新設定。
14. As an 操作員, I want 監控中也能切換語言, so that 不需停止測試才能讀懂畫面。
15. As an 操作員, I want 待確認時也能切換, so that 可理解裁決內容而不失去候選。
16. As an 操作員, I want 所有已開 App 視窗同步更新, so that 不必面對多種介面語言混用。
17. As an 工程師, I want 切換保留尚未保存的輸入, so that 語言變更不清除配置編輯。
18. As an 操作員, I want 切換保留衝突選取及原候選快照, so that 不會對另一項衝突誤操作。
19. As an 操作員, I want 切換不自動確認警報或人工裁決, so that 最終決定仍由我完成。
20. As an 操作員, I want 關閉保存期間暫停語言切換並說明原因, so that 保存流程保持一致。
21. As an 操作員, I want 取消關閉後恢復語言切換, so that 返回工作時仍可選擇語言。
22. As an 操作員, I want 主畫面、設定、警報、衝突、保存及錯誤內容都可理解, so that 英文模式不只翻譯表面按鈕。
23. As an 操作員, I want 畫面先前出現的事件也隨語言更新, so that 可閱讀既有經過。
24. As an 工程師, I want SN、檔名、路徑及原始 Log 保持原值, so that 翻譯不改變證據。
25. As an 工程師, I want 狀態碼、來源時間語意及 KVM 契約保持, so that 語言不影響結果判斷與上位機。
26. As an 操作員, I want 缺少單項翻譯時顯示英文, so that 不會看到空白或內部識別碼。
27. As an 操作員, I want 錯誤先有可理解的本語言說明, so that 知道需要處理什麼問題。
28. As an 工程師, I want 詳細區保留原始診斷, so that 能追查實際系統錯誤。
29. As an 台灣開發人員, I want 所有 App 事件有繁中說明, so that 能快速查閱問題經過。
30. As an 美國現場工程師, I want 同一事件有英文說明, so that 能與開發端對照同一次操作。
31. As an 工程師, I want 兩語同筆紀錄共用事件時間與識別, so that 不會產生兩份不同步紀錄或重複操作。
32. As an 工程師, I want 保存訊息識別與參數, so that 畫面可重新呈現而不猜測翻譯原文。
33. As an 工程師, I want 語言切換不重寫磁碟內容, so that 原事件與證據保持可靠。
34. As an 工程師, I want 舊檔案不被改寫, so that 更新 App 不改變既有稽核資料。
35. As an 操作員, I want 可辨識舊訊息以所選語言顯示, so that 能閱讀過去紀錄。
36. As an 工程師, I want 無法辨識舊內容保留原文詳細資訊與翻譯外層提示, so that 不會以猜測翻譯掩蓋原始內容。
37. As an 工程師, I want 沒有輪次的啟動、配置或熱鍵事件也有雙語紀錄, so that 問題不只留在畫面。
38. As an 工程師, I want App 層事件沿用全域保存期限且不清理待補存資料, so that 磁碟用量可控又不妨礙故障恢復。
39. As an 工程師, I want 畫面與事件共用中英術語, so that 同一概念不出現不同譯名。
40. As an 工程師, I want 翻譯集中管理、驗證後隨 App 發布, so that 現場不需匯入未驗證文案。
41. As an 工程師, I want 未來新增畫面語言仍保持固定繁中／英文紀錄, so that 不需隨語言數量重做保存契約。
42. As an 操作員, I want 原生檔案選擇器保持系統操作方式, so that 不因 App 翻譯而改變選檔結果。
43. As an 操作員, I want 長英文與語言選單不遮住必要操作或 KVM 標記, so that 語言改善不破壞測試流程。
44. As an 工程師, I want 發布前完整檢查兩語及關鍵提示, so that 裁決、警報及保存失敗文字不依賴漏譯回退。

## Implementation Decisions

### 語言資源與契約

- 首版語系為美式英文與繁體中文，集中翻譯資源及共用術語；使用穩定訊息識別與明確參數，翻譯文字不得作流程判斷、事件身分或狀態碼。
- 初始術語沿用已確認對應：Test Round、Awaiting Review、Station Type、Original Result、New Candidate、Source Time、Source Filename。新增術語先統一，畫面與事件共用。
- 翻譯資源與 App 一起版本化、驗證及發布，不支援現場匯入或自動在線翻譯；簡體中文與西班牙文僅為未來擴充方向，不列首版選項。
- 缺少單項翻譯回退英文，不出現空白或內部鍵值；英文是完整基準資源，兩語鍵與參數完整性需發布前驗證。缺少英文基準或關鍵操作提示不得宣告可發布。
- 參數保留 SN、路徑、來源檔名及平台資料原值，不用英文語言選擇改變時區、日期格式、來源時間證據或解析策略。

### 直覺語言入口與持久設定

- 主頁右上角提供目前語言加展開提示的按鈕，例如 English ▾／繁體中文 ▾；不用國旗、單一抽象圖示或內部語系代碼代替名稱。
- 一次點擊展開，直接選取切換，選項有原生名稱與當前勾選；支援鍵盤開啟、選取及取消，不增加套用按鈕。取消或重選目前語言不重複改變操作狀態。
- 首次無設定時英文；全域持久語言設定獨立於 profile，啟動讀取上次選擇。配置編輯、儲存及匯入匯出不得意外抹除它；未知或已不支援的語言值回到英文並保留可理解的診斷。
- 語言設定保存失敗可見，不虛稱已持久保存；目前畫面仍可安全使用選定語言，問題需進入雙語 App 事件與既有保存復原流程。

### 即時刷新及操作安全

- 在監控中及待確認時只刷新文案，不重啟監控、不清除結果、候選或警報，不自動執行操作。
- 已開主畫面、設定、衝突、警報、保存及 App 錯誤視窗使用同一語言；保留未保存輸入、選取、候選快照與視窗操作狀態，不用關閉重開達成翻譯。
- 畫面已顯示的可識別事件依訊息識別與參數更新，不重新執行事件、不變動時間／序號／結果。快速連續切換不產生混用語言或反覆綁定回呼。
- 關閉保存期間停用入口並以目前語言說明；取消關閉後恢復。原生檔案選擇器系統文字遵照作業系統，App 提供的標題、類型及說明使用選定語言；不重新開啟選檔視窗或代替使用者選取。
- 需同步換語言的訊息／錯誤提示改由 App 管理，保留原操作效果及必要互斥，不擅自將需要確認的流程改為自動確認或取消。
- 英文長文字與語言選單不得遮住 KVM 色帶、固定定位及黑白狀態標記；保留幾何、色彩、產品狀態碼及上位機契約。必要文案換行或配置調整須在真實 Tk 驗證。

### 固定雙語事件與歷史相容

- 所有 App 產生的事件說明同筆保存繁中、英文、穩定訊息識別、參數及必要原始診斷，使用同一事件身分及原事件時間；只有實際屬於輪次的事件才關聯輪次。
- 相容擴充既有 audit／Session 保存契約，保留機器欄位與既有讀取能力；擴充須有明確版本及可驗證的解讀方式，不以重寫舊檔方式遷移。兩語說明不是兩筆事件，不新增第二次人工操作。
- 紀錄生成時固定兩語並保留原始參數，不隨目前介面語言改變；之後切換或更新翻譯資源不回寫過去說明。新版本讀取有識別的事件可依目前資源顯示，磁碟保存的當時兩語說明仍可查閱。
- 未來新增顯示語言使用訊息識別與參數，硬碟仍固定繁中／英文；無法套用新資源的事件可回退其保存英文說明，不丟棄原始診斷。
- 舊紀錄只在可靠匹配既有事件契約時翻譯顯示，不以模糊比對或在線猜測改變證據；無法辨識時詳細區保留原文，外層使用所選語言說明。
- 保存故障保留整筆雙語事件供重試，不讓單語先成功被判為完整；沿用既有有序重試、跨輪未保存追蹤及完整保存才關閉的行為。

### 無輪次 App 事件與保存期限

- App 啟動、配置、匯入匯出、熱鍵及偏好等沒有輪次的事件有 App 層紀錄，使用自身時間與事件識別，不虛構 round_id，不用輪次已封存判定取代其保存狀態。
- App 層事件沿用全域保存天數，從事件原時間起算，使用帶時區時間及一致到期比較；輪次紀錄仍從可信封存時間起算，兩者不可混用。
- 清理只處理可信、完整保存且到期的 App 事件；待保存、保存失敗、未知或損壞資料保留。清理單位可採可驗證紀錄段，但不得因段內部分事件到期而刪除其他未到期或受保護事件。
- App 層事件清理與既有背景清理排程、全域期限、保存及關閉狀態協調，留下摘要；新增資料範圍不擴張到任意外部檔案、配置、人工匯出或平台來源。
- 初始化或磁碟故障時仍提供可理解訊息；可取得的待保存事件完整保留後重試，不承諾能即時寫入正在故障的磁碟。診斷保存失敗不得遞迴產生無限保存失敗事件。

### 交付方式

- 沿用共同輪次、平台來源、配置及桌面介面分工；集中翻譯與事件表示契約，避免各平台自行翻譯同一操作。
- 以相容擴充先建立翻譯／事件形式，再分可驗證操作路徑接入主頁、設定、衝突、警報、保存及 App 診斷；每一批保持既有行為與測試可驗證，不一次替換全部機器契約。
- 每批相關及既有全套檢查通過、更新實際證據後 commit／push。正式 bundle 的翻譯資源完整收錄須於發布驗收確認，不以 source App 測試代替目標 bundle 驗證。

## Testing Decisions

- 使用者已確認多語言討論中的真正 Tk、共同輪次、注入時鐘與磁碟重建驗收方向；沿用實際 App 操作入口及共同輪次公開行為，資料用真實暫存檔，不為各語言另造業務流程。
- 良好測試檢查實際可見文字、選單操作、保留的輸入／選取／結果、雙語磁碟內容及重建結果，不以私有 helper 呼叫數或 widget 階層作唯一驗收。
- 沿用現有 Tk 衝突／警報／保存重試與取消關閉、profile 持久設定、audit 相容重建、有序故障恢復及封存清理測試作法。翻譯資源完整性可獨立驗證資料契約，但不是 UI 與保存行為的替代。

### 必要驗收案例

1. 無設定首次英文，繁中切換後重啟仍繁中；配置保存、匯入匯出及換機型不抹除語言，設定寫入故障可見。
2. 右上入口顯示目前語言，English／繁體中文可直覺辨識且有勾選；滑鼠及鍵盤可選取／取消，重選不改監控狀態。
3. 監控中及待確認切換不重啟、不清除結果、候選或警報，事件身分、數量與時間不因切換改變。
4. 全部已開自有視窗及既有畫面事件同步翻譯；未保存輸入、選取、快照與人工裁決狀態維持，連續切換不殘留舊語言。
5. 關閉保存入口停用且原因可讀，取消關閉後恢復；保存狀態、重試及關閉的既有效果維持。
6. 原生選檔系統文字例外明確，App 提供的說明仍翻譯；選檔取消、覆寫確認與返回路徑不變。
7. App 错誤顯示翻譯說明與原始診斷；警報、裁決及保存失敗兩語完整，缺少一般翻譯回退英文，不顯示空白或鍵值。
8. 全部翻譯資源鍵、參數與術語一致，首版只列兩種語言；缺少英文基準或關鍵提示不得通過發布完整性檢查。
9. 輪次及非輪次事件同筆有繁中／英文、識別、參數及必要診斷；語言切換前後磁碟原紀錄不重寫，不產生重複操作。
10. 新雙語事件有序保存與重建，部分寫入或保存失敗後仍保留整筆，修復重試不缺語言、不重複；無輪次錯誤不遺失於單純 UI 記憶體。
11. 舊檔讀取前後內容完全一致，可可靠識別則翻譯，不可識別保留原文詳細與翻譯外層提示；新舊 audit／Session 相容。
12. 注入事件時間驗證 App 層期限之前、恰到與之後，保存失敗／待補存及未知資料不清理；輪次仍按封存時間處理。
13. 改全域期限、清理與保存競爭、清理失敗及摘要可讀均有證據，不刪除其他資料範圍。
14. 兩語主畫面、長文字、全部主要彈窗與語言選單在實際 Tk 可讀可操作，KVM 標記／色帶不遮擋、固定契約與上位機判定維持。
15. 相同平台資料與人工決定在兩語下產生相同結果、候選、逾時、未知來源 FAIL、放行與 audit 操作身分，差異僅人員文案。
16. 發布產物收錄完整語言資源，source 與 bundle／目標環境證據分開；現有全套回歸及必要圖形案例通過才宣告對應範圍交付。

真正 Tk 測試使用可存取桌面工作階段的環境；必要案例因環境未執行需明記待驗，不以 mock、語法或文件檢查冒充。此次規格交付未執行產品測試或宣告實作完成。

## Out of Scope

- 首版簡體中文或西班牙文翻譯；德州工廠對西語的實際需求調查。
- 現場匯入外部翻譯檔、自動在線翻譯、下載語言套件或隨系統語言自動切換。
- 操作手冊與其他專案文件翻譯、作業系統語言設定及原生選檔系統文字控制。
- 翻譯 SN、來源資料、檔名、路徑、原始診斷或機器狀態碼；因語言修改來源時間解析、時區或日期格式。
- 改變同輪判定、未知來源 FAIL、人工裁決、產品放行或 KVM 色帶／標記契約。
- 重寫歷史紀錄、以猜測翻譯宣告來源證據、每新增畫面語言即增加硬碟保存語言。
- 自動清理任意外部檔案、改工程師配置保存期限，或以 App 事件時間取代整輪封存時間。
- 本次規格撰寫不包含程式實作、拆票、實機部署、正式 bundle 建置或強制程序終止下的恢復保證。
