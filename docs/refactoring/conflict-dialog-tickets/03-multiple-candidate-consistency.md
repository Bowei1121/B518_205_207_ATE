# C3：多候選覆核與持續刷新維持雙區資訊一致

## Parent

Part of GitHub 規格 Issue #9。草案，待使用者確認後發布。

## What to build

操作員在同位置多候選、不同位置切換、新候選加入、逐項裁決及隱藏重開時，上下兩區與紅色粗體始終對應同一待裁決項目。原選項被移除後呈現正確後續候選，沒有候選時清空舊值與樣式，避免對錯誤內容操作。

## Acceptance criteria

- [ ] 同位置與跨位置多候選選取時，精簡、詳細及差異樣式對應同一衝突識別，不混用不同捕捉快照。
- [ ] 持續刷新及新候選加入保持仍有效的選取，原選項消失後沿用既有後續選取行為。
- [ ] 裁決移除、全部處理完成、短暫沒有有效選取及隱藏重開時，上下同步刷新或清空，不留下前項內容及樣式。
- [ ] 捕捉後修改來源不悄悄更新候選；原／新不是時間先後或自動採用建議。
- [ ] 保留原／採用新／關閉仍逐項作用於所選衝突，關閉視窗不自動裁決；其他位置收集不受阻擋。
- [ ] 未知同輪候選仍依既有 FAIL 政策，不因精簡區新增人工採用；audit 重建、停止收集與放行分離及 KVM 契約維持。
- [ ] 真正 Tk 驗證完整多候選操作、持續刷新、空狀態與重開；共同輪次及磁碟結果回歸通過，全部 12 組規格案例有證據。
