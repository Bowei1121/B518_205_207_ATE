# 配置與輪次啟動組裝討論

日期：2026-10-08

狀態：A1–A7 與完整討論結論已由使用者確認；已要求轉為規格，未開始程式實作。

## 背景與目標

架構分析報告以 d0f4535 為基準，指出 Tk 的 `start_monitor` 同時理解配置驗證、平台監控建立、位置映射、回呼建立順序，以及 Session／audit 配置快照。最新核對基準為 4d7754c；其新增衝突視窗改動未改變這項候選的核心啟動流程。

目標是集中啟動準備知識、提高 Module 的 Depth 與 Locality，讓未來平台變更取得 Leverage。這不是效能量測結論，也不承諾監控速度提升。

## 已確認決策

### A1：改動範圍

集中按下開始監控後的啟動準備流程：選定配置與路徑驗證、本輪配置固定、平台監控程式建立、來源／顯示位置映射，以及 Session／audit 配置資訊準備。

工程師設定畫面、配置匯入匯出、監控中的結果判定維持原責任。本次以維持既有行為與穩定性為優先，保留保存與關閉安全機制。

### A2：提示相容性

保留既有錯誤提示文字、出現時機與操作效果。翻譯由後續多語言工作處理。

### A3：分階段交付

程式測試與桌面操作驗證完成後可先交付；文件保留現場驗收項目。未完成現場驗收時，不宣稱實際工廠資料與設備已驗收。

### A4：啟動準備與輪次管理分工

啟動準備 Module 集中檢查並固定選定測試配置，以同一份固定配置建立平台監控、位置對應，以及 Session／audit 配置資訊，避免兩份紀錄各自解讀配置。

原輪次管理 Module 保留接受開始、背景準備排程、逾時、停止與保存責任；Tk 保留按鈕、畫面與錯誤提示。這項決策不把輪次生命週期搬入啟動準備 Module，也不改變接受開始與來源就緒兩個時點。

### A5：待確認啟動差異另案修正

本次保留待確認時各開始入口的既有行為，加入對應驗證。將「待確認時所有開始入口都不產生副作用」列為獨立待修項目，與本次架構改造各自驗收；目前僅記錄於本文，尚未建立遠端議題或實作修正。

### A6：兩階段遷移

1. 建立集中管理的啟動準備 Module，透過其 Interface 直接驗證配置檢查、位置對應、Session／audit 配置資訊一致性；此階段尚未切換 Tk 正式啟動路徑。
2. Tk 改用集中準備流程，完成所有既有支援平台的驗證後，移除 Tk 重複組裝程式；正式交付保留單一啟動流程。

所有既有平台完成程式與桌面驗證後才交付。不在正式版本長期維護新舊兩套啟動規則。現場驗收仍依 A3 另階段執行。

### A7：行為測試方式

- 透過啟動準備 Module 的 Interface 直接測試，不必建立 Tk 畫面；使用真實暫存目錄與測試資料驗證路徑、配置快照及位置對應。
- 使用可控制的測試監控程式，配合既有輪次管理測試入口與可注入時鐘，重現準備緩慢、建立失敗及準備途中停止；輪次生命週期測試仍由原 Module 負責。
- 保留既有平台解析與 ConfiguredMonitor 雙向映射行為測試，及真正 Tk 的按鈕、快捷鍵、錯誤提示與畫面狀態測試。
- 測試驗證可觀察的結果與副作用，不以函式呼叫次數或 mock 呼叫鏈作為主要驗收。

## 查證的現有行為（非新增需求）

- Tk 先驗證配置與來源路徑，再顯示啟動中；同步保存偏好成功後，才呼叫 RoundCoordinator 接受開始。
- 輪次接受開始與來源準備完成是兩個時點。來源在背景準備，其時間計入整輪期限。
- 來源背景準備失敗保留失敗輪次與事件；準備期間停止，來源回來後不得重新開始收集。
- Session 與 audit 配置資訊均由同一個選定 profile 產生，但目前在 Tk 分別組裝。
- ConfiguredMonitor 的雙向位置映射有實際責任，不能當作空轉發刪除。
- 快捷鍵阻擋 RUNNING 與 AWAITING_REVIEW；直接 start_monitor 只前置阻擋 RUNNING。待確認時 Coordinator 不建立新輪，但 UI 仍可能先驗證、保存偏好及重設畫面。依 A5 保留差異並另案修正，不默認為純重構。

- `B518 Log Solution/src/b518_log_solution.py:614–617,648–659`：快捷鍵啟動限制。
- `B518 Log Solution/src/monitoring_round.py:226–245,640–698,1215–1241`：輪次接受、背景準備、失敗與重複啟動。

## 後續規格須保留的行為

以下由程式查證而得，並依使用者要求保留既有行為；屬於後續規格與驗收條件，不新增產品政策。

- 無效配置或路徑不接受新輪次；空白路徑不解讀為目前目錄。
- 偏好保存成功後才接受新輪次；偏好保存失敗時沿用既有錯誤處理與畫面恢復。
- 接受開始時間與來源準備完成時間分開；背景準備時間仍計入整輪期限，不移到準備完成後才計時。
- 背景準備失敗仍保留失敗輪次與保存責任，不刪除已產生的紀錄。
- 準備中停止或逾時後，來源稍後準備完成不得重新啟動收集。
- ConfiguredMonitor 保留來源與顯示位置的雙向映射，以及未映射來源的證據處理。
- 保留 RUNNING 重複開始、AWAITING_REVIEW 各入口差異與關閉保存中拒絕開始的既有行為；A5 修正另案。
- 舊輪次延遲事件不得覆寫新輪次畫面；改造不破壞跨輪保存追蹤、封存及期限清理保護。
- 提示文字、出現時機與操作效果維持一致；本次不引入多語言實作。
