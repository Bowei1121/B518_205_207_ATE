# 人工衝突彈窗精簡資訊討論

日期：2026-10-07（Asia/Taipei）。使用 grill-with-docs 的 grilling 與 domain-modeling 流程；此文件記錄討論，不代表產品實作完成。

## 使用者已指定的方向

- 左側維持衝突選單。
- 右上新增精簡資訊欄位，內容比較衝突前後資訊。
- 右下維持原有詳細資訊，提供較完整內容。
- 目的是減少人工覆核時資訊過多、過雜，讓操作員先掌握差異，再按需要閱讀細節。

## 第一輪已確認答案

- 精簡區固定顯示結果、SN、來源時間與來源識別四項，明確標記差異。
- 差異以紅色粗體呈現，不只依顏色區分。
- 來源顯示名稱及路徑差異已於第二輪確認，見下節。

## 第二輪已確認答案

- 精簡區的來源欄位稱「來源檔名」，平常只顯示內容來自的檔案名稱；完整來源路徑及原來源識別維持在詳細區。檔名是閱讀提示，不取代既有來源身分判定。
- 原結果與新候選路徑不同但檔名相同時，補上可區分兩者的簡短目錄提示並標記差異；無來源時顯示「未知」。
- 不同欄位的原結果與新候選兩側值都採紅色粗體，相同欄位維持一般文字。
- 右側精簡區約 40%、詳細區約 60%，中間可拖曳調整；左側選單及底部操作按鈕維持原位。
- 切換左側選取時上下資訊同步更新。

## 完整呈現方案（待最後共識確認）

1. 左側維持衝突選單，右側上下分區，底部維持「保留原結果／採用新結果／關閉」。
2. 右上以「項目／原結果／新候選」對照，固定列出結果、SN、來源時間及來源檔名；保留所選顯示位置的識別。
3. 原結果是已接受結果，新候選是捕捉當下待裁決資料，不保證時間先後；來源時間沿用平台提供的時間語意，不改稱統一的測試結束時間。
4. 差異兩側值紅色粗體；檔名相同但路徑不同時加簡短目錄提示。缺少欄位沿用「未知」，不以 App 觀察時間或檔案修改時間補造。
5. 右下維持既有完整詳細內容，包括輪次、衝突及來源證據。初始 40%／60% 分區可拖曳，不增加新的人工裁決操作。
6. 上下區域皆來自同一 conflict_id 的捕捉快照，不重新讀檔；切換選取、處理某項、沒有待處理項目時同步刷新或清空。持續刷新沿用既有選取保持行為，避免畫面顯示不同候選。

## 後續驗收方向

- 真正 Tk 驗證固定四項、原／新對照、不同值兩側紅色粗體及相同值一般文字。
- 驗證不同檔名、同名不同路徑、相同來源原地更新及缺少來源／時間等情境，完整路徑仍可在詳細區查閱。
- 驗證可拖曳上下分區、既有視窗最小尺寸可操作、左側選取與底部按鈕原位保留。
- 驗證多候選選取、候選處理後移除、沒有候選及隱藏後重開時，上下顯示同步且無殘留。
- 保留非模態彈窗、其他位置繼續收集、逐項人工裁決、未知同輪 FAIL、audit 及 KVM 契約。

政策與呈現已逐項確認；完整方案待使用者最後共識確認。產品程式尚未修改，尚未執行上述新增驗收。

保留既有逐項人工覆核、停止收集與放行分離，以及未知同輪來源不得人工採用的政策。待討論形成共識後才修改產品程式；本次 UI 呈現方向可逆，尚無需要新增 ADR 的架構取捨。
