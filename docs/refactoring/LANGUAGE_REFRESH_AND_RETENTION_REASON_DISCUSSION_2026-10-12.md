# 多視窗語言更新與清理原因表述討論

日期：2026-10-12

狀態：A1–A11 及完整結論已由使用者確認，已要求轉規格，未開始程式實作。

## 背景

延續 2026-10-09 架構分析的第一、二項。使用者以 LabVIEW User Event 廣播通知類比第一項：語言切換發出通知，各視窗更新文字並保留操作狀態。此類比不代表新增通用事件機制、替各視窗開背景執行緒或更換 Tk。

第一項集中視窗語言刷新知識，提高呈現 Module 的 Depth、Locality 與 Leverage；第二項集中清理原因語意，讓畫面不必以中文字串猜測底層原因。尚未決定具體 Interface。

## 已確認決策

### A1：先限定語言更新

所有 App 自有視窗接收語言更新通知並保留操作狀態。監控結果、保存與關閉流程沿用現有機制，不擴張為全部程式事件的通用廣播。Tk 畫面仍由既有畫面執行流程更新；原生檔案選擇器維持系統行為。

### A2：一起規劃、分開驗收

兩項一起規劃、分開實作與驗收。第一項處理視窗更新與狀態保留，第二項處理清理原因說明；每項可獨立驗證。

### A3：單一視窗更新失敗隔離

其他視窗繼續更新，保留失敗視窗的操作內容，顯示可理解提示並記錄診斷。不因此中斷監控，也不自動關閉重開失敗視窗。

### A4：清理原因範圍

涵蓋輪次紀錄、App 事件清理，以及判斷能否清理時的封存驗證原因。統一說明方式，刪除資格仍由原本安全檢查決定。

### A5：未知原因與舊紀錄

無法可靠辨識的原因，外層以所選語言提示「無法辨識此原因，請查看詳細資訊」，詳細區保留完整原文。不猜測翻譯、不改寫舊紀錄，不因辨識失敗放寬清理條件。

### A6：視窗通知生命週期

開啟時登記一次、關閉時解除；重開直接使用目前語言。暫時隱藏而未關閉的視窗，再次顯示時也須使用目前語言。

使用者詢問是否要記住當下語言，開窗先讀狀態。規劃沿用 App 目前語言作為共同依據，開窗讀取後呈現；各視窗不另存獨立語言偏好。磁碟偏好依原機制保存，供下次 App 啟動恢復。

### A7：更新失敗重試

顯示一次彙整提示並記錄診斷，提供「重試文字更新」；只更新文字，不重開視窗或重啟監控，不持續自動重試。使用者同意先採此方案；提示位置及驗收方式已由 A9、A10 確認。

重試應讀取 App 最新語言，不套用已過時的失敗通知。此為遵循目前語言共同依據的設計說明，不新增語言偏好保存政策。

### A8：新清理摘要與舊格式相容

新摘要保存固定原因識別、相關參數與原始診斷，保留繁中／英文說明供直接查閱。畫面依原因識別呈現所選語言；識別不能取代原本刪除安全檢查。

舊摘要不改寫，可可靠辨識的舊原因照常翻譯，其餘依 A5 保留原文。具體相容資料格式由後續規格設計，不預定版本數字。

### A9：非阻擋失敗提示

採用主畫面一則不阻擋操作的提示，附「重試文字更新」及詳細診斷入口。多視窗失敗合併提示，不連續跳窗；全部恢復後清除提示，診斷紀錄保留。使用者同意試用此方案，應以 A10 桌面驗收確認其操作效果。

### A10：分項行為驗收

第一項使用真正 Tk，驗證多視窗切語、關閉重開、隱藏後顯示，以及單一視窗故意更新失敗。確認其他視窗正常更新、草稿與選取不變、重試採用最新語言；非阻擋提示與恢復效果亦納入驗收。

第二項使用真實暫存紀錄，驗證新摘要雙語保存、舊摘要相容、未知原因完整原文，以及原清理刪除／保留結果不變。分別驗收兩項並保留既有行為測試，不只驗證通知方法被呼叫。

### A11：逐步遷移

第一項沿用既有語言通知機制，先補齊視窗登記／解除、失敗隔離與重試，再逐步接入各視窗。全部驗證通過後移除主畫面逐一呼叫視窗更新的舊流程，避免通知與舊流程重複更新；每個遷移步驟均須驗證行為。

第二項先建立新舊摘要讀取能力，再讓清理程式產生帶原因識別的新摘要，最後讓畫面使用集中原因說明。舊摘要保持原樣，既有清理安全與耐久保存不變。兩項分別交付。

## 延續的既有契約

- 切語不清除草稿、輸入、候選與事件選取、閱讀位置，不關閉重開視窗。
- 不重新啟動監控、不改結果、不自動裁決或確認警報，不重寫已保存事件。
- 關閉保存期間暫停切語；語言偏好保存失敗依既有方式處理。
- 封存／事件起算、待保存保護、完整性與符號連結檢查不變。
- 遵循 ADR 0005 與 0007–0009；尚無需新增或重議 ADR，也不把實作通知寫入 CONTEXT.md。

## 已查證背景與限制

先前唯讀基準為 4b6efd7：自有提示視窗已有語言變更通知登記並於關閉解除；其他視窗仍以主畫面串列刷新。清理摘要以原因原文保存，Tk 以中文全文或前綴辨識，未知原因直接顯示原文。已有真正 Tk 的跨視窗、草稿、選取、閱讀位置與磁碟不改寫測試可沿用。
