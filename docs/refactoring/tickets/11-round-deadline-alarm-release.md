# 11：整輪上限、一次警報與確認後放行

**類型：**新增

**What to build／工作內容與交付結果：**整輪從接受開始起算上限，到期停止收集、保留已有結果並顯示一次待確認警報，必要確認完才放行。

**Blocked by／前置依賴：**

- [07：工程師畫面編輯、匯出及部署配置](07-profile-editor-import-export.md)
- [10：共同處理已確定同輪的結果衝突](10-same-round-conflict-review.md)

**Status：**blocked（前置任務完成後；另依本票外部前置檢查）

## 驗收條件

- [ ] 來源準備、進度與彈窗不重設上限，UI 不被準備阻塞而失去期限處理。
- [ ] 整輪尚未完成而上限到達立即停止新讀檔；已有終態保留、未開始 NOTEST、已開始未完成 TIMEOUT。
- [ ] 到期只產生一次警報且程式待確認，後續推進不重複報警。
- [ ] 警報確認不接受或清除結果衝突；仍有衝突時不可取用。
- [ ] 候選保留，全部必要確認完成才放行；沒有人工確認倒數。

## 驗證方式

模擬到期前後與混合 PASS／FAIL／未開始／測試中／衝突，操作警報及衝突並驗證釋放。

**規格驗收對照：**AC-13、AC-14、AC-18

## 保留決策、待確認事項與限制

這是整輪監控上限，不是彈窗倒數；未知來源人工採用仍交由 18。

所有行為測試須依 01 的接口確認結果落實；本次批准任務清單不代表測試接口已獲批准。未知同輪來源能否人工採用仍由 18 決定，任何本票的已完成部分都不能抵銷該未決分支。
