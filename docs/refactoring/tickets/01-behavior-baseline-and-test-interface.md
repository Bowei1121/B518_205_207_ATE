# 01：建立行為保護基準並確認測試接口

**類型：**前置

**What to build／工作內容與交付結果：**整理三平台樣本、回放與現有測試，建立可重現的保護基準；區分應保護行為、預期改變的 MVP 行為及待驗限制，並取得主要測試接口的明確確認。

**Blocked by／前置依賴：**

無；基準整理可立即開始。

**Status：**needs-decision（基準整理可開始；測試接口確認後才能完成）

## 驗收條件

- [ ] Atlas、B482、RS-WMT 的匿名化樣本與回放可重現，原始資料保持只讀。
- [ ] 既有解析、操作及打包保護項目有基準與結果證據；固定容量、七格色帶、整輪無活動 TIMEOUT、完成後三秒觀察等被標為預期變更，沒有誤列成新版保護條件。
- [ ] 規格 AC-01 至 AC-28 均有後續任務與驗證方式；跨任務驗收標明分工，不以局部通過宣稱整項完成。
- [ ] 主要測試接口取得使用者明確確認或修訂，結果有紀錄；尚未確認時不得勾選完成。

## 驗證方式

沿用現有公開輪詢、可注入時鐘、事件與暫存來源回放；形成保護／變更／待驗清單。

**規格驗收對照：**AC-01～AC-28 的驗收對照與測試接口確認

## 保留決策、待確認事項與限制

測試接口仍未決：配置啟動一輪 → 樣本 Log／模擬時間／輪詢 → 通道結果與程式狀態 → 人工選擇／確認警報 → 停止收集及可取用。本次同意拆票不等於接受此接口。基準整理可先開始，接口定案前不完成本票。

所有行為測試須依 01 的接口確認結果落實；本次批准任務清單不代表測試接口已獲批准。未知同輪來源能否人工採用仍由 18 決定，任何本票的已完成部分都不能抵銷該未決分支。

## 執行與追蹤

依 2026-09-30 使用者確認的任務清單建立。以 REFACTOR_SPEC、CONTEXT 與 ADR 0001～0005 為基準，沿用測試配置、平台資料來源、監控輪次、桌面介面四模組與 Python／Tk／既有 macOS 打包方式。只在前置完成且本票關鍵待決及外部條件已滿足時轉為 ready-for-agent；需要人類決策的任務不得逕自轉為可直接實作。

執行時逐項記錄實際交付、驗證環境與結果、仍未決／待驗範圍及相關提交。未執行的驗收維持未勾選；本文件建立不代表 App 已完成重構。
