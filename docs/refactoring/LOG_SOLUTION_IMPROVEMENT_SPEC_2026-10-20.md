## 修改範圍

1. 集中歷史事件查詢的互動流程，保留既有操作與固定查詢結果。
2. 集中開始監控的非畫面流程，正確分類錯誤，按鈕與快捷鍵共用規則。
3. 增加監控經過時間、全狀態 App 畫面心跳及輪次耗時紀錄。
4. 開發與打包以 Python 3.12.10 及指定套件版本為共同驗證基準。
5. 提供橋接交接規格；橋接程式由使用者與 Claude 另行修改，本輪不修改橋接專案。

維持既有產品結果、衝突、逾時、人工停止、復位、資料保存及清理政策；不將結果可交付改成必須等待補存完成。保存／封存／清理的大範圍架構候選不納入本輪。

## 監控經過時間

| 情境 | 顯示與紀錄 |
| --- | --- |
| App 開啟，尚未開始新輪 | `00:00`；歷史紀錄不改寫 |
| 開始前配置／路徑驗證失敗，新輪未受理 | 保留上輪顯示時間，不能假裝新輪已開始 |
| 本輪開始受理 | 歸零並開始計時，包含來源準備時間 |
| 來源準備中、監控中 | 持續顯示經過的分秒 |
| 尚有衝突，但仍在收集其他位置 | 繼續計時 |
| 停止讀取本輪 Log | 停表，固定最後時間 |
| 正常完成、人工停止、逾時、取消、受理後啟動失敗 | 以該輪停止收集的時刻停表並保留數值 |
| 停止收集後待人工確認、重試保存或封存 | 時間不再增加 |
| 下一輪受理 | 才重新歸零 |
| 意外超過 15 分鐘 | 繼續，例如 `15:01`；不得回零或截斷 |
| 關閉再開 App | 畫面回 `00:00`；舊輪最後時間仍可從輪次紀錄查證 |

時間由輪次本身持有，採單調時間差計算，避免系統時鐘校正造成倒退；畫面更新不能成為計時來源。畫面忙碌後恢復時須顯示真實經過時間，不能以「每次畫面回呼加一秒」累加。

停止時間只定案一次；補存、人工確認及重繪不得改變最後耗時。不得從舊紀錄缺少的欄位虛構耗時。新增耗時欄位須可由新讀取端辨識缺值並繼續讀取歷史紀錄，既有紀錄不批次改寫。

持久化的精度、欄位名稱與讀取相容性於實作設計時確定；畫面只顯示分秒。顯示至少兩位分鐘；若將來超過99分鐘，不得以取餘數假裝回到00分鐘，實際可容納字寬須驗證。

## 固定顯示位置

- 監控狀態與時間在同一行，使用兩個獨立顯示區。
- 計時區位置固定，不依賴 Tab 字元，也不受狀態文字或中英文長度影響。
- 數字固定字寬，秒數兩位；一般格式 `MM:SS`。
- 長狀態文字應在其自身區域內處理，不可擠動、蓋住計時區。
- 計時區的實際座標、字型、字級、邊距、前景／背景與可辨識範圍須在實作驗收後提供給橋接。

## App 畫面心跳

- 四格採與狀態標記相同的2×2外觀與尺寸；純黑 `#000000`、純白 `#ffffff`。
- 使用0～15的16態二進位計數，每0.5秒加一，15後回0；完整週期8秒。
- 心跳不作計時器計數，不隨測試開始重設或測試結束停止；橋接只作該區有效影像差異比較，不需解碼數字。
- 由Tk畫面更新流程驅動；待命、準備、監控、待確認、完成、故障待復位與可操作的關閉保存期間都持續，直到畫面銷毀。
- 不用獨立於畫面運作的背景工作偽造「畫面仍活著」；畫面更新卡住，心跳也必須停止。
- 卡住後恢復不得只按牆上時鐘推算計數，跳到剛好與舊畫面相同的循環狀態而掩蓋停頓；具體排程與恢復行為須以測試驗證。
- 心跳不逐次寫入輪次／App事件紀錄；其用途為畫面觀察，不產生每半秒一筆的永久資料。

### 幾何限制

心跳放在狀態標記正右側、同一列；狀態標記可向左移，保留兩個定位點與結果格位置。若遠端每小格不足12×12 px，狀態與心跳兩組一起放大。

現行狀態外框26×26、內格10×10，為Tk單位，不等於遠端像素。須以橋接實際取得且經縮放／壓縮的影像確認至少12×12 px，不能以本機Retina畫面替代。

現行 `x=278` 的狀態格右邊到 `x=320` 右定位點之間不足以塞入同尺寸心跳；不能直接追加而重疊。精確新座標與兩組最終尺寸尚未凍結，須實作量測，不得當成目前已可供Claude使用的固定數字。

## 橋接觀察的語意

| 證據 | 可確認的事 | 不能據此推論 |
| --- | --- | --- |
| 新鮮可讀影格中的心跳持續變化 | 心跳區畫面持續更新 | ATE已開測、結果可交付、所有背景工作皆正常 |
| 本次開始操作後的計時數字增加 | 本次開始流程已受理的輔助證據 | 來源已準備完成、允許啟動ATE |
| 狀態標記進入本次監控就緒 | 來源準備完成，依既有契約可啟動ATE | ATE已實際開始測試 |
| 本輪可信活動或有效結果 | ATE測試開始證據 | 所有通道都已開始或全部PASS |
| 既有可交付狀態及完整結果 | 依原契約交付 | 可略過衝突或警報確認 |

計時必須與本次開始請求的觀察流程連結；上輪殘留的非零數字不能當本輪已開始。快速完成可能來不及觀察兩個不同秒數，不能新增「一定看過計時增加才可交付」的門檻；維持ADR0010／0011的就緒與同輪證據規則。

橋接預期每秒觀察一次；使用者同意連續三張有效影像心跳相同就回報異常。三張影像的時間為t0、t0+1、t0+2秒，跨度約2秒，不是完整3秒。可見性、影格新鮮度、取樣中斷、8秒循環及雜訊處理見交接稿。

## 歷史事件查詢整理

將查詢、首次結果、完整準備、翻頁、詳細資料、取消、重試、結果取代與關窗的共同規則集中到「歷史事件查詢 module」的implementation，讓Tk adapter透過同一seam使用；不只搬計時器或增加shallow module。interface應減少畫面必須理解的識別與呼叫順序，提升depth、locality與leverage；不在本文件先定新方法名稱。

保留查詢操作、排序、固定查詢結果、翻頁、詳細資料、語言切換與閱讀位置；新舊請求交錯時舊回覆不能覆蓋新畫面。取消不銷毀仍可讀的已公布內容；重試延續同份固定結果，不悄悄重查來源。釋放結果要由明確擁有者處理，不能關窗後殘留工作反寫畫面，也不能提早釋放仍在讀取的內容。

## 開始流程整理

深化既有開始準備module，保留配置固定、平台建立與位置映射；畫面只傳操作與呈現。按鈕、快捷鍵共用受理規則；不得因重複操作或晚到來源準備工作建立第二輪。

分清取得／驗證配置、保存設定、建立／啟動來源與畫面呈現的失敗；錯誤分類應對應真正失敗步驟。已開始的輪次不能因呈現錯誤而假裝不存在，不能把所有例外標成設定保存失敗。維持故障紀錄、人工確認／復位與不自動重試規則。

## Python 3.12.10 影響與基準

- 現有macOS15打包已要求Python3.12與原生arm64；本次基準明確到3.12.10。現行檢查只核對3.12，後續需使檢查與文件一致。
- macOS15相依基準：PyInstaller6.16.0、PyObjC core／Cocoa／Quartz11.1，依現有requirements安裝；不藉本次任意升版。
- 開發與打包需記錄實際Python、虛擬環境與套件；git pull不能同步虛擬環境。
- `datetime.utcfromtimestamp()`為已棄用寫法，現在仍可執行；整理歷史查詢時可改用對應UTC寫法，但須保持原本時區轉換及回傳語意。
- 本機是Intel／macOS15.8.1，不能代替M4／arm64目標驗收。Tk初始化abort的根因尚未確認，不認定為3.12相容性故障。
- 本規格不改動其他macOS交付目標；各目標仍各自檢查套件與bundle相容性。

## 驗收矩陣

| 項目 | 必須觀察的結果 |
| --- | --- |
| 準備／監控／人工確認 | 準備時計時，停止讀檔即固定；確認與補存不增加時間 |
| 人工停止／逾時／取消／準備失敗 | 保存對應原因與固定耗時；心跳繼續 |
| 新輪／開始前失敗／App重開 | 分別歸零、保留上一輪、畫面00:00且歷史耗時可讀 |
| 時鐘校正與畫面暫停 | 耗時不倒退、不靠畫面回呼累加；心跳不能假裝停頓期間持續更新 |
| 大於15分鐘／跨分鐘 | `14:59→15:00→15:01`正常，秒數進位與最後耗時一致 |
| 中英文及最長狀態文字 | 計時位置固定，長文字不覆蓋它 |
| 心跳全狀態／半秒／循環 | 每0.5秒一步，16態循環，停止輪次後仍更新，銷毀後不留回呼 |
| 來源準備或磁碟工作緩慢 | 畫面可操作、心跳持續；真正阻塞畫面時心跳必須停 |
| 歷史查詢交錯／取消／關窗重開 | 晚到舊工作不蓋新結果，已公布固定內容仍可讀，無資源誤釋放 |
| 開始按鈕／快捷鍵／失敗復位 | 同規則、無重複輪次，錯誤分類及紀錄正確 |
| KVM幾何／縮放／壓縮／遮擋 | 定位點與色帶不位移；狀態與心跳各自可讀，每小格至少12×12遠端像素 |
| 三張同圖／正常心跳／8秒取樣空隙 | 同圖異常、正常不誤報；取樣中斷不得假裝連續觀察 |
| 舊輪次紀錄與故障重試 | 歷史缺欄位仍可讀，補存不重複、不改最後耗時 |
| Python／打包／桌面 | 指定版本檢查、相關測試、真實Tk操作、bundle及目標機配對驗收 |
