# 規格：Log Solution 架構優化、監控計時與獨立畫面心跳

狀態：使用者A1～A16及驗收入口已確認；可交由agent實作，產品功能尚未實作或驗收。
規格整理基準：`bd5d4b8`。本規格取代同名文件先前的敘述版，原始訪談及Claude交接稿保留。

## Problem Statement

操作員看不到本輪監控已花多久，停止後也缺乏可查證的最後耗時。橋接雖可收到持續更新的KVM影格，卻不能據此確認App畫面仍在更新；計時若在完成後正常停止，也不能拿來當全狀態心跳。

歷史事件查詢的取消、結果取代、翻頁、詳細及關窗狀態散在畫面程式；開始監控的多種失敗也共用過大的錯誤處理範圍，容易顯示不相符的原因。開發環境已切換Python3.12.10，需要明確的共同驗證基準，避免開發、打包與目標機的結果混為一談。

## Solution

增加固定位置的分秒計時，從本輪開始受理算到停止讀取Log，保留並保存最後耗時；新增每半秒更新的獨立四格黑白心跳，在所有可操作狀態持續顯示。計時只輔助判斷本次開始已受理，監控就緒、ATE實際開測及結果交付各保留原有證據要求。

集中歷史查詢與開始流程的共同規則，保留既有操作與產品政策，讓錯誤原因正確、晚到工作不干擾新操作。以Python3.12.10及指定套件作為共同基準，並提供足夠的實測資料讓Claude接續橋接修改。

## User Stories

3. 作為操作員，我希望用分秒閱讀監控時間，以便不用換算秒數即可理解本輪耗時。
4. 作為操作員，我希望在來源準備及監控期間持續看到時間增加，以便掌握本輪等待多久。
5. 作為操作員，我希望在仍收集其他位置而有衝突時繼續計時，以便不漏算尚在進行的監控時間。
6. 作為操作員，我希望停止讀取本輪Log時立刻停表，以便區分監控耗時與人工處理時間。

8. 作為操作員，我希望人工停止後保留停止當下時間，以便記住中止前已耗費的監控時間。
9. 作為操作員，我希望監控逾時後保留最後時間，以便讓警報確認等待不改變監控耗時。
10. 作為操作員，我希望取消本輪或受理後啟動失敗時保留該輪最後時間，以便查證失敗流程已進行多久。

## Implementation Decisions

### 1. 測試輪次與監控經過時間

- 監控輪次module持有計時事實；畫面呈現既有操作入口回傳的輪次狀態，不自行建立第二份開始／停止判定。沿用輪次操作、狀態快照及輪次紀錄的既有interface，不只為計時另建平行流程。
- 本輪受理時歸零，包含來源準備；仍收集其他位置時，即使已有衝突也繼續計時。停止收集時固定最後耗時，正常完成、人工停止、逾時、取消及受理後啟動失敗遵守同一原則。
- 停止後的人工確認、補存、封存與畫面重繪不得增加或重新定案耗時；新輪受理前驗證失敗保留上輪顯示時間。只有下一輪受理才歸零。
- 採單調時間差，不能由畫面回呼次數累加，也不能受系統時鐘校正影響。畫面忙碌恢復後顯示真正經過時間。
- App重開畫面為00:00；最後耗時保存於對應輪次紀錄，且與輪次身分、停止原因一致。保存重試不能重複或改寫最後耗時；延續既有完整保存後關閉政策，不增加結果交付的保存前置條件。
- 以相容擴充加入耗時資料；既有缺值紀錄仍可讀、不改寫、不由檔案時間或猜測補造數字。欄位名稱與保存精度屬實作細節，須在交付文件說明並驗證相容讀取。

### 2. 固定位置的分秒顯示

- 監控狀態與計時在同一行、各有獨立區域；計時位置不受狀態文字長度或中英文切換影響。使用固定字寬數字，不靠Tab字元撐出位置。
- 一般格式為MM:SS，秒數00～59、分鐘至少兩位。超過15分鐘繼續顯示，例如15:01；不得截斷、回零或以取餘數假裝重新開始。對較長分鐘數須保留可讀與不重疊的呈現，不新增小時欄位。
- 停表後數值繼續顯示；狀態文字須在自己的區域處理，不能覆蓋計時。實際字型、字級、尺寸及裁切範圍由桌面實作量測後凍結交接。

### 3. 獨立App畫面心跳

- 四格為2×2、二進位0～15循環，每0.5秒加一，15後回0，完整週期8秒。純黑與純白，不用漸層、陰影或抗鋸齒效果模糊小格。橋接只比對該區影像有效差異，不要求解碼計數。
- 心跳由Tk畫面更新流程驅動，待命、準備、監控、待確認、完成、故障待復位及可操作的關閉保存期間都持續，直到畫面銷毀；不與本輪計時一起停止，也不因換輪重新起算。
- 畫面更新阻塞時心跳必須停，不能用與畫面獨立的背景工作偽造更新。恢復策略須讓實際停頓可被觀察，不能用事後時間推算來宣稱停頓期間正常更新。
- 心跳回呼的生命週期由畫面統一管理，銷毀後不得殘留；不為每半秒心跳寫永久事件紀錄。
- 心跳與狀態標記同尺寸，位於其正右側、同一列；狀態標記可左移，兩個定位點及結果格位置保留。遠端每小格須至少12×12像素，不足時兩組一起放大。
- Tk單位不等於遠端像素；以實際接收的縮放／壓縮影像驗收。新座標、格間隔、留白及最終尺寸是實作需產出的量測結果，本規格不捏造未量測的固定值。

### 4. 橋接觀察契約與交接責任

- 心跳變化只證明其畫面區持續更新，不證明所有背景工作正常、ATE開測或產品PASS。狀態標記與心跳區須各自可讀，相鄰不能取代遮擋檢查。
- 本次開始後計時增加，是本次開始流程已受理的輔助證據；來源準備期間也計時，所以仍須看到本次監控就緒才可啟動ATE，ATE已開測則依可信測試活動／有效結果確認。
- 不得以殘留非零時間認定本輪開始；也不得新增「一定看到兩個不同秒數才可交付」門檻，因快速輪次可能來不及觀察秒數增加。交付沿用既有同輪、完整結果及待確認規則。
- 使用者預期橋接每秒觀察一次，連續三張有效、新鮮、可讀的影像心跳相同即回報異常。每秒一張時，三張從第一到第三跨度約2秒，不是完整3秒，也不是基準圖之外再三次相同。
- 壓縮雜訊不能當成有效心跳，重複舊影格、遮擋或觀察中斷不能假裝連續有效取樣。心跳8秒循環，間隔8秒整數倍的同圖不能單獨證明凍結；須結合連線與影格新鮮度資訊，保留原因待查分類。
- 本輪交付App顯示契約、實測幾何、格樣、固定計時範圍、影像樣本、相容版本與驗收證據；橋接程式由使用者與Claude另行修改。顯示契約版本不等於TCP協定版本。
- 橋接的最大允許觀察間隔、中斷重設、恢復門檻及上位機錯誤處置，明列為橋接工作後續決策，不能冒稱本次已定案；不得因此繞過既有人工復位或自動重測。

### 5. 歷史事件查詢深化

- 保留查詢、首次公布、後續準備、翻頁、詳細、診斷、取消、重試、語言切換及關窗操作。歷史事件查詢module的interface應讓呼叫端不用各自管理多份請求與結果擁有權；相關implementation集中，Tk adapter只傳操作並呈現狀態。
- 既有查詢、分頁與詳細工作仍可在內部合作；只把計時器搬檔、增加轉呼叫module或重複狀態，不算完成。本次deepening以depth、locality及leverage是否實際增加判定，不以檔案大小或數量判定。
- 晚到的舊查詢、分頁或詳細結果不得覆蓋更新的請求；關窗後舊回覆不能影響重開的視窗。
- 取消不銷毀仍可讀的已公布結果；重試繼續同份固定查詢結果，不能悄悄重查來源。後續新增、替換或清理來源，不改變已公布內容與排序；無法取得的資料須如實回報，不偽造。
- 語言切換保留目前日期草稿、固定結果、頁面、選取及閱讀位置。結果資源須由明確擁有者釋放，不能提早關閉仍在讀取的內容，或關窗後遺留資源。

### 6. 開始流程深化與錯誤分類

- 沿用既有開始準備、固定配置、平台資料來源建立、位置映射與監控輪次分工；把剩餘非畫面協調集中，按鈕與快捷鍵共用受理規則。
- 關閉中、已有啟動故障待復位、已有不可重入輪次等情境，維持既有開始限制；重複操作與晚到的準備結果不得另建輪次或重新開測。
- 分清取得／驗證配置、保存設定、建立／啟動來源與畫面呈現等錯誤；顯示與紀錄要對應真正失敗原因，不將各種例外都報為設定保存失敗。
- 已受理或已開始的輪次不能因畫面錯誤而假裝不存在；保留輪次、原始診斷、人工處理及復位要求，不自行重試。既有產品結果、待確認與取消語意維持。

### 7. Python共同基準與相容性

- 開發與打包共同以Python3.12.10作驗證基準，環境檢查需核對實際修訂版、執行環境與目標架構，不能只檢查3.12或依賴殼層命令名稱。
- macOS15套件沿用目前指定的PyInstaller6.16.0及PyObjC core／Cocoa／Quartz11.1，不在本輪任意升版；記錄虛擬環境及套件版本。取得程式更新不代表套件環境同步更新。
- 整理已棄用的UTC時間轉換寫法時保留原本時區換算與回傳語意。既有Tk初始化崩潰原因尚未確認，不認定為Python升級造成，也不能以匯入成功當桌面驗收。
- Intel開發測試、真實Tk桌面、arm64打包及M4／macOS15目標驗收分開記錄；不變更其他既有macOS交付目標。

## Testing Decisions

### 已確認的驗收入口

使用者已確認以下三個seam；優先沿用現有高層操作，必要的非同步協調留在module內，不為每個helper新增測試入口。

1. **實際輪次操作與保存結果**：透過既有開始準備、監控輪次操作與狀態快照，檢查真實輪次紀錄及重試後結果；不靠直接修改內部旗標證明正確。
2. **歷史查詢完整操作流程**：由查詢module對外操作入口走完查詢、分頁、選取詳細、取消、重試、換查詢及關閉生命週期；只有必要時集中既有操作形成同一seam，不新增平行helper介面。
3. **真實Tk畫面與KVM配對影像**：透過實際按鈕／快捷鍵、語言切換與視窗生命週期驗證呈現；以真實接收影像驗證像素與壓縮影響，不拿手工拼圖替代。

### 好測試的判準

- 驗證操作員、橋接或紀錄讀取端可觀察的行為；內部函式數量、呼叫順序、私有旗標與檔案拆分不是通過標準。
- 時間相關核心測試沿用可注入的單調時鐘，檢查跨秒、停止定案與時鐘校正；桌面測試仍須觀察真實排程與繪製，不以假時鐘取代半秒顯示驗收。
- 非同步案例控制完成先後，真正製造舊回覆晚到、取消及關窗情境；不能只單測純函式卻跳過它如何被呼叫。
- 保存相關測試使用暫存磁碟及重新讀取的真實值，驗證失敗重試、無重複、耗時不改寫與歷史缺欄位相容。
- 新功能需先取得能驗證實際行為的證據；既有173項通過、語法檢查或過去打包成功不算本功能已完成。

| T05 保存與重開 | 保存失敗可重試、最後時間不變、不重複；新程序可讀舊輪耗時，畫面00:00；舊紀錄缺值不造假 |
| T06 時間正確性 | 系統時鐘校正不倒退；畫面暫停不漏算；14:59→15:00→15:01正常，較長分鐘數不回零 |
| T07 固定計時區 | 中英文、最長狀態、不同容量與縮放下，計時位置不動且不被遮住 |

| T09 畫面生命週期 | 實際阻塞畫面時心跳停，恢復不宣稱期間持續更新；慢來源／慢保存不阻塞正常畫面 |
| T10 KVM幾何 | 狀態／心跳同尺寸、同列、互不重疊；定位點與結果格不移位；遠端每小格≥12×12像素 |

| T12 橋接交接案例 | 三張有效同圖的定義明確；正常半秒心跳不誤判；8秒循環／觀察中斷不冒充連續觀測 |
| T13 證據區分 | 上輪非零時間不證明新輪開始；計時增加不代替就緒／ATE活動；快速完成不額外阻擋交付 |
| T14 查詢交錯 | A後送B，A晚回不蓋B；舊分頁／詳細回覆不覆蓋新選擇 |
| T15 固定結果與取消 | 取消後已公布內容仍可讀；重試不重查來源；語言切換保留日期、頁面、選取及閱讀位置 |
| T16 關窗與資源 | 關窗後舊工作不反寫重開視窗；讀取中的結果不提早釋放，無遺留工作 |
| T17 啟動失敗分類 | 分別製造配置、保存、來源及呈現錯誤，原因正確且仍保留對應輪次／紀錄／復位規則 |
| T18 防重入與晚到工作 | 按鈕與快捷鍵連續開始不多建輪；準備中停止後晚到來源不重新啟動 |
| T19 Python與發布 | 核對3.12.10／套件／架構；執行相關測試、真實Tk、bundle與目標機驗收；記錄實際版本及證據 |
