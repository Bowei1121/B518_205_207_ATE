# T2：本輪保存失敗可有序重試，且不漏寫或重複

## Parent

Part of GitHub 規格 Issue #1。草案，待確認後發布。

## What to build

操作員能在本輪保存失敗時看見原因、保留原工作，修復後從 App 重試，取得完整且可重建的 Session 與 audit。此票先交付單輪的完整復原路徑，使用 T1 的工作者生命週期，不只新增儲存層 API。

## Acceptance criteria

- [ ] UI 呈現等待、保存中、失敗與完整保存，提供不阻塞視窗的重試；重複操作不建立並行重試。
- [ ] Session／audit 的背景寫入、同步 enqueue／append、初始化及保存位置關聯失敗均保留必要恢復資料，不能僅以 pending 歸零或 flush 成功判定完整。
- [ ] 暫時故障解除後依原序號、內容及時間有序補存，部分寫入及追加後故障不漏寫、不重複，也不覆蓋有效紀錄。
- [ ] Session 最終結果、事件、來源 metadata、人工操作與 audit 完整一致，停止收集後人工操作仍可保存及磁碟重建。
- [ ] 歷史錯誤及恢復結果可查，但不再被誤認為目前未保存；故障回報不遞迴產生無限失敗事件。
- [ ] 保留既有落盤、來源同輪、未知 FAIL、產品放行及 KVM 契約；舊紀錄可讀。
- [ ] 高層故障／修復測試與真正 Tk 重試操作測試通過；持續故障時 UI 仍有回應。

## Blocked by

- T1：完成輪次後回收 audit writer，人工操作仍可保存。
