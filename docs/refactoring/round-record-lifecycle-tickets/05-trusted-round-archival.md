# T5：完整保存的已結束輪次產生可信封存時間

## Parent

Part of GitHub 規格 Issue #1。草案，待確認後發布。

## What to build

已結束且沒有待確認事項的輪次在全部必要資料完整保存後，留下可信、可驗證的封存資訊，作為保存期限起點。共同輪次與 App 可觀察封存狀態，歷史缺少證據的資料維持可讀並保留。

## Acceptance criteria

- [ ] 同時滿足已結束、無待確認、完整保存才持久封存；停止讀檔或排空不能單獨造成封存。
- [ ] 等待人工確認或保存修復數天後，使用實際封存時刻，不使用開始監控、來源時間、檔名或 mtime。
- [ ] 封存契約包含版本、輪次身分、帶時區時間及可驗證完整性資訊，仍可用既有方式讀取與重建紀錄。
- [ ] 同輪早期 audit 與 Session 分散時聚合判定；任何組成部分未知、損壞或未完整保存時不宣告可信封存。
- [ ] 後續必要操作尚未保存時取消可清理資格；共同狀態及 UI 能區分未保存與已封存。
- [ ] 舊資料缺少可信封存時間時保留，不猜測或補造；注入時鐘及磁碟重建驗證所有條件。
