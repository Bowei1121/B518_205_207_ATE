# T7：背景清理到期整輪紀錄，保留摘要並可恢復失敗

## Parent

Part of [規格 Issue #1](https://github.com/Bowei1121/B518_205_207_ATE/issues/1)。依 ADR 0007／0008 與已確認拆票方案實作。

## What to build

App 依工程師設定，於啟動後、持續開啟每 24 小時及設定修改後安排背景清理。只刪除到期、已結束且完整保存的整輪紀錄，UI 不中斷；留下持久摘要，失敗下次安全重試。此票才啟用自動刪除，必要保護與故障恢復同票完成。

## Acceptance criteria

- [x] 封存時間加目前有效保存天數判定到期，涵蓋期限前、恰到期限與期限後；新期限適用所有可信既有輪次。（注入時間及真實磁碟驗證 180／365 天邊界、縮短／延長設定與每日排程。）
- [x] 同輪多目錄聚合後整輪清理，刪除前重新檢查完整性及保護狀態；活躍／本次受保護、無可信封存、未知、損壞及組件不一致資料保留。（含 Ticket 05 封存資格與本票清理保護測試。）
- [x] 刪除限 App 管理且可信列出的輪次資料；配置、偏好、人工匯出、來源 Log、未知文件及符號連結外部資料保持完整。（真 Tk 檔案前後比對及磁碟競爭故障注入。）
- [x] 背景工作合併多個觸發且不重疊；關閉保存期間不啟動新清理，既有工作與新增保存安全協調，UI 保持可操作。（Event 協調及真正 Tk `after` 心跳。）
- [x] 摘要記錄時間、使用期限、輪次、刪除／跳過／失敗及原因；輪次資料刪除後仍能查看摘要，摘要寫入失敗可見且不虛報成功。（新 Coordinator 重讀 ledger、摘要故障注入及 Tk 摘要檢視。）
- [x] 單輪失敗不停止其他安全候選；多目錄部分刪除失敗保留可恢復進度，下次不誤判剩餘資料或重複虛報整輪完成。（涵蓋 stage rename crash、期限延長、ledger 故障與 fresh Coordinator 復原。）
- [x] 以公開協調入口、注入時鐘、真實暫存檔及實際 Tk 驗證排程、設定變更、完整清理、保護、保存競爭、關閉競爭、故障恢復及摘要。（完整套件 274 項通過；真 Tk 設定與摘要案例於桌面 session 執行。）
- [x] 完成母規格 16 項必要驗收案例覆蓋查核；新舊資料讀取、產品放行及 KVM 契約維持。受控測試未冒充現場設備驗收。（逐案對照見本機驗收紀錄。）
