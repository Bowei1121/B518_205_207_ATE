# QP2：可靠總數與前500筆先發布

## Parent

[規格 #46](https://github.com/Bowei1121/B518_205_207_ATE/issues/46)。

## What to build

操作員送出查詢後，先取得確定總筆數及全部頁數，再一次看到最新最多500筆；其餘內容持續背景分批整理，前五頁不需等全部完成即可閱讀。

## Acceptance criteria

- [ ] 先確認所有適用來源版本與可靠正常事件總數；不能略過未核實來源、估計頁數，或以未知總數先發布結果。不可讀來源仍明示既有不完整警告。
- [ ] 首批發布原子對應同一條件／時區／版本／排序／總數／頁數與最新最多500筆，每頁100筆；涵蓋0、1、99、100、101、499、500、501，零筆總頁數為0。
- [ ] 準備期間保留舊結果與原日期；首批及總數成功後才替換。區分首批可讀與全部完成，總數不因尚未備妥批次或後續故障改寫。
- [ ] 首批後有限批次繼續處理後面的內容，不等第六頁要求才開始；總數計算不先複製全結果原文，已公布次序及內容不漂移。
- [ ] 首批前後與進度沿用最新世代、取消及關閉隔離；後續批次不在Tk執行緒做大量讀取／格式化，不能為趕首批破壞固定原文或基本回收。
- [ ] 用Event／Barrier暫停後續整理，真正Tk仍可連續讀前五頁、選取詳細及切語言；驗證結果不是callback提早、實際閱讀卻仍等全批完成。
- [ ] 小固定混合來源與原檔基準完整對照，日期／DST、空結果與異常回歸；分開記錄總數、首批與全部完成時間。

- [ ] 本票必要功能測試、真正桌面與相關回歸通過後可合併；維持既有行為保護，不把後票完整驗收提前當本票前提。工廠驗收獨立追蹤，不阻擋合併；大型補驗需有具體風險理由，不默認每票數小時重跑。
