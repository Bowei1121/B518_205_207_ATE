# QP6：成本對照與完整交付驗收

## Parent

[規格 #46](https://github.com/Bowei1121/B518_205_207_ATE/issues/46)。

## What to build

用相同資料及runtime證明首批可讀時間與重複完整內容複製成本下降，完成整份規格與必要產品回歸；避免無理由重跑數小時極端容量。

## Acceptance criteria

- [ ] 記錄固定修改前基準，主要採固定小／中混合來源的單日及近7天，涵蓋少於與超過500筆；資料不是現場精確分布。
- [ ] 各主要成本情境至少三次短時量測，分報來源確認／索引同步、總數、排序、首批可讀及全部完成，不把總時間全歸因於複製。
- [ ] 比較同fixture／日期／runtime／追蹤條件，揭露冷暖與tracemalloc差異；首批可讀含全部必要前置工作，重複完整內容複製量也需下降。
- [ ] 記錄列表數、複製bytes／筆數、持久衍生量、記憶體與worker；不以提前callback或較少解析次數替代實際可閱讀及資源證據。
- [ ] 小固定集合完整核對原檔身分／排序／原文，首次建立與故障恢復分報並處理退步；未訂硬性秒數或RAM上限，不擅加門檻。
- [ ] 真正Tk與必要相關完整回歸通過，42項故事及驗收矩陣對照最終程式；相容入口與舊批次路徑收尾不留繞過版本／快取規則的入口。
- [ ] 大型補驗只針對具體風險，事先列目的、規模與停止條件；不預設每票216萬筆五情境三次全頁核對，未跑據實揭露，H8資料僅歷史基準。

- [ ] 本票必要功能測試、真正桌面與相關回歸通過後可合併；維持既有行為保護，不把後票完整驗收提前當本票前提。工廠驗收獨立追蹤，不阻擋合併；大型補驗需有具體風險理由，不默認每票數小時重跑。
