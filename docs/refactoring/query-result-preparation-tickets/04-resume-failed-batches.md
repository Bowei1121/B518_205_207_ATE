# QP4：後續批次失敗與同版本重試

## Parent

[規格 #46](https://github.com/Bowei1121/B518_205_207_ATE/issues/46)。

## What to build

首批前失敗保留舊結果，首批後失敗保留新結果及閱讀位置；操作員只重試尚未完成部分，沿原固定版本繼續，不能混入新事件。

## Acceptance criteria

- [ ] 首批前失敗／取消保留舊日期及結果；無舊結果也可區分未查詢、失敗與取消，不發布假空結果。
- [ ] 首批後背景故障保留已發布範圍、總數、頁面與可讀詳細，標示尚未完整取得並提供真正App重試入口，不誤稱沒有更多資料。
- [ ] 重試只繼續未完成部分，沿同一固定版本；恢復後排序、身分與原文一致，新事件僅在重新查詢後納入。
- [ ] 原版本確實無法恢復時明確提示重新查詢，不能偷偷重建成新版本卻宣稱續傳。
- [ ] 保留來源無有效日期、不可讀與不完整保存的原文／診斷，索引失效可安全降級，失敗來源不永久快取成成功。
- [ ] 取消後不自動繼續處理，重試／重查由使用者觸發；過期重試、故障與進度不得覆蓋較新查詢，既有固定內容不被過早回收。
- [ ] 以真實索引／檔案故障、可控制批次與真正Tk驗證前後失敗、恢復、版本失效及雙語提示，查詢不回寫原始bytes。

- [ ] 本票必要功能測試、真正桌面與相關回歸通過後可合併；維持既有行為保護，不把後票完整驗收提前當本票前提。工廠驗收獨立追蹤，不阻擋合併；大型補驗需有具體風險理由，不默認每票數小時重跑。
