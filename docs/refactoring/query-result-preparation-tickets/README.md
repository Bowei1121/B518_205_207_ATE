## 執行與交付界線

先從QP1開始，先讓目前實際查詢能重用固定原文；QP2再接入可靠總數與500筆首批發布。QP3與QP4可依直接依賴分別完成快取閱讀與失敗重試，QP5做共同生命週期／回收競態整合，QP6作成本及全規格驗收。

每票都必須維持既有原文、世代、取消及回收安全，不把基本保護留給後票才修。QP1未承諾首批預載，QP2不等於窗口及所有恢復案例已完整交付；中間階段可合併，但不能宣稱父規格完成。

不依賴HM組完成；以短區間／小中fixture做成本比較，首批可讀時間必須包含可靠總數前置工作。不預設每票數小時216萬事件流程，不把提早callback當體感改善。

每票必要開發、真正桌面與相關回歸通過可合併，最後一票驗收全規格。工廠／實體設備／正式部署另追蹤，不阻擋開發合併；未驗收項目不能冒充通過。建立票件不是程式實作完成。
