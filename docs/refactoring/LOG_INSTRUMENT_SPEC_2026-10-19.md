# B518 Log Solution 儀器狀態、人工停止與顯示契約 1.2 規格

日期：2026-10-19（Asia/Taipei）  
狀態：需求及本專案驗收範圍已確認；待實作與驗收。此規格不代表產品已完成。  
依據：本輪討論定稿、領域詞彙、ADR 0010／0011，以及跨專案狀態辨識交接；本次使用者確認的「只驗收本程式可驗證事項」優先於早期跨專案驗收建議。

## Problem Statement

上位機需要把 Log Solution 當成可控制的儀器：先確認它能收集本輪 Log，再讓 ATE 開測，最後可靠取得完整結果。現行畫面容易把「已接受開始」「正在準備來源」「可收集 Log」及「ATE 實際測試活動」混在一起；人工停止會回落待命而無法交付，準備中停止又可能缺少完整格位，現場也缺少一致的啟動失敗／人工復位規則。

FCT 改成先監控、後推治具時，短的開始期限可能過早定案 NOTEST；完全沒有開測的情況又必須明確警報，不能當成正常完成。視窗可能被 ATE 遮住，現有前景行為還會強制鍵盤焦點；左定位點則未涵蓋色帶左緣，令顯示契約不夠直接。

本專案需交付可由自己驗證的狀態、結果、紀錄及桌面輸出；KVM 畫面辨識、傳輸與上位機流程由 KVM_Log／LabVIEW 各自驗收，有問題再提出回饋，不作為本專案完成的前置條件。

## Solution

保留單工站整輪、既有平台解析與 Python／Tk，明確區分 READY、BUSY／準備中、BUSY／監控中、BUSY／待確認及兩種 READY 完成狀態。開始命令接受後固定配置並鎖定；來源基準完成後才發布監控就緒。狀態格表達整輪／儀器狀態，色帶保留逐格產品結果，TESTING 或有效結果另作為實際測試活動證據。

人工停止保留已完成結果，只將未完成格定案 STOPPED，並以獨立人工停止完成圖樣交付。來源準備、全輪未開始及啟動失敗都須有明確停止、待確認與復位行為；不能證明畫面同輪時，交接規則要求人工核對、取消並保留紀錄，不強制交付或自動重測。

FCT 已存配置開始期限先採 120 秒；指定事件提升視窗但不永久置頂、不強制焦點；新增準備中與人工停止圖樣、移左定位點並同步顯示契約 1.2。驗收只涵蓋既有公開輪次行為、磁碟重建及真正 App／Tk 輸出，另提供 KVM_Log 開發所需的輸出契約資料。

## Implementation Decisions

1. **維持既有分工。** 測試配置管理部署參數；平台資料來源 adapter 解讀格式與可信證據；監控輪次 module 統一管理準備、結果、期限、衝突、停止及交付；桌面介面呈現及接收操作。不建立第二套與既有輪次平行的狀態機，不以本次名義全面重構 UI、保存生命週期或歷史查詢。
2. **沿用最高既有 seam。** 業務 interface 以輪次協調公開操作、輪次／App 狀態快照及磁碟重建為主。來源準備及 App 層失敗／復位必要的可觀察資訊可在該 interface 做最少擴充；Tk 不自行判定結果可交付，測試不依賴私有欄位拼湊另一套規則。藉此讓 implementation 吸收時序複雜度，增加 depth、locality 與跨平台 leverage。
3. **接受開始與監控就緒分離。** 接受開始時固定本輪配置、建立身分並鎖定；其後顯示 PREPARING，完成來源舊檔基準、必要關聯及準備後才 MONITORING。不可先發 MONITORING 再補舊檔基準。物料就緒由上位機掌握，Log 不感知或推測治具狀況。
4. **所有開始入口一致。** 按鈕、視窗內／全域快捷鍵及核心公開入口，在準備中、監控中、待確認、未復位啟動失敗及關閉保存期間都不能建立新輪。重複開始不清空結果、不重做來源準備、不重設期限；完成後的新命令才可建立下一輪。
5. **READY／BUSY 是儀器能力，非產品結果。** READY 可以等待新輪或保留已交付／可交付畫面；BUSY 包含準備、監控及待確認。主畫面同時說明具體階段，不能只用一個 BUSY 文字代表可以開測。
6. **六種狀態圖樣。** 四格順序是左上、右上、左下、右下；1 黑、0 白。採下表，保持所有合法圖樣兩黑兩白；未知、缺格、低對比一律不猜測。PREPARING 可以很短，不要求外部必然採到，但它不能等同 MONITORING。

| 狀態 | HMI | 位元 | 可交付條件／意義 |
| --- | --- | --- | --- |
| STANDBY | READY／待命 | 1001 | 無可交付的本輪結果 |
| PREPARING | BUSY／準備中 | 0101 | 已接受本輪，來源尚未就緒，不可開測 |
| MONITORING | BUSY／監控中 | 1100 | 已完成本輪來源準備，可允許上位機觸發 ATE |
| REVIEW | BUSY／待確認 | 1010 | 結果衝突、警報或啟動失敗未處理，不可開測或交付 |
| COMPLETE | READY／完成 | 0110 | 一般整輪結果完整且無待確認，不表示全 PASS |
| MANUAL_STOP_COMPLETE | READY／人工停止 | 0011 | 人工停止、完整格位已定案且無待確認 |

7. **REVIEW 優先。** 未處理衝突、未確認警報或未復位啟動失敗，優先於完成及 READY；App 層錯誤即使沒有新輪也須能顯示 REVIEW。單靠狀態格不區分全部根因，HMI 與紀錄保留具體原因及診斷。
8. **可交付須明確完整。** 一般完成與人工停止的結果可交付判定，都不能與未處理衝突／警報矛盾；格位須恰好涵蓋本輪配置容量且全為終局，不能只用空集合判定、不能漏格或重複格。既有來源位置至顯示位置映射保持，不能把來源編號當成色帶位置。
9. **人工停止保留事實。** 已完成終局結果保留，未完成位置改 STOPPED，通道及色帶用同一狀態，維持灰色而不轉成 FAIL。整輪保留 manual_stop 原因及可交付種類；不以是否含 STOPPED 格推測人工停止，不偽造一般完成事件。
10. **準備中停止立即定案。** 來源尚未建立時，依固定配置建立全部位置的停止結果；可見結果不等待來源 factory 返回。停止後遲到的來源工作成功／失敗都不能重新開測、改成其他完成種類或覆蓋已定案結果。尚有原待確認事項時維持 REVIEW，逐項處理後才可交付。
11. **FCT 配置更新。** 目標 FCT profile 的 start 期限先採 120 秒，從接受開始監控計時，包含準備耗時；設定變更維持已支援格式可獨立更新配置的政策。更新實際已存／匯入且被選取的 profile，不只改新建預設；DFU／BT 保留自己的設定。每輪凍結期限，不在準備完成時重算起點。
12. **完全無開始證據的警報。** 到開始期限時，整輪尚無可信活動也無有效結果，停止收集，未開始格定案 NOTEST，建立一次未偵測到開始的警報並維持 REVIEW；人員確認且無其他待確認後才可完成。不將原因直接命名為 ATE 當機。來源準備尚未返回時，亦不得因建立新警報而繼續等待至原本更長的整輪上限才處理開始期限；警報可確認時機須確保既有結果及停止裁決一致，晚返回不得覆寫裁決。
13. **保留分格與整輪期限。** 部分位置已有活動／有效結果時，不額外套用整輪完全無開始警報；其他未開始位置依既有規則處理。測試期限與整輪監控上限仍有效；原已定案結果不變，整輪逾時及衝突不得被新開始警報自動確認。
14. **期限先於該次讀檔。** 到期輪詢先套用 deadline 再讀來源；期限前尚未被程式接受的證據，不因該次稍後讀到或來源自報早期時間而挽回。期限前已接受的活動及結果保留；不新增完成後觀察寬限或人工確認倒數。
15. **測試活動與監控就緒分離。** TESTING、COMPLETING 及可靠的本輪有效測試結果可表達某通道活動；WAITING、NOTEST、TIMEOUT、STOPPED、MONITORING 或 HID 操作成功不單獨證明 ATE 已開始。不要求先有 TESTING 才能接受有效最終結果，不由一格推論全部通道已開始。
16. **啟動失敗與復位。** 接受前配置／路徑／其他同步啟動失敗，記 App 層失敗請求，不補造新輪或錯掛上一輪；接受後來源準備失敗，停止並保留失敗輪次。兩者顯示 REVIEW、鎖定新開始，明確顯示原因，不生造產品 FAIL 或人工停止完成。人員排除問題、確認並復位後，已建輪次取消、未建者結束失敗請求，才回 READY；下次明確觸發才新輪。關閉提示不等於復位，復位不刪紀錄或自動操作 ATE／治具。
17. **同輪性不足的交接。** 橋接未觀察本次 MONITORING 就人工停止或準備逾時，交接規則要求需人工核對、不自動交付／重測；人員確認警報不取代同輪證據。操作員核對後取消、保留結果及處理紀錄、排除問題後另開新輪，不提供強制採用不確定結果的捷徑。Log 本地須提供可取消／復位及可查核事實，但不實作橋接的同輪判讀器或協定。已可靠保存且可確認的既有結果重傳不因本決策一律取消。
18. **保存及重建。** 新事件保存原始狀態、人工停止／取消／復位／期限原因及必要身分，保持有序重試、不漏寫不重複。新讀取者從磁碟重建後須與公開快照的結果、原因及本地可交付語意一致；若紀錄契約需相容擴充，採明確版本或事件語意，不假造一般完成、不重寫舊檔、不將歷史 1.1 停止推定成 1.2 已放行。來源資訊不足仍依既有未知候選政策，不能與橋接同輪不明的取消政策混淆。
19. **不變的保存政策。** 產品結果放行與 audit／Session 完整保存／封存分開，不新增保存成功的交付前置。未保存輪仍追蹤，完整保存後才正常關閉，保存失敗可恢復；封存時間起算、資料保護及非輪次資料範圍不變。新增文案及事件保持繁中／英文及原始診斷。
20. **前景提升。** 開始監控、可信 TESTING、結果更新與整輪完成時提升視窗；同批事件可合併，狀態未變不因輪詢重複提升。避免強制鍵盤焦點，不永久 topmost；同時保留 Review 操作及標記可見性。真正桌面行為須驗證，不能只刪一次 focus_force 就宣稱成功。
21. **定位點變更。** 移除 KVM RESULT 字樣，不移到其他位置；左定位點左緣對齊或超過第一格色帶左緣，維持左右 22×22、同高及不對稱內嵌白格。四周至少 2 Tk 單位白留白，不裁切、不與其他標記／色帶重疊；不得為滿足留白擅自移動其他契約元素。第一格原點 x=0 的情況須以父框可繪範圍與實際畫面證明，不直接假設負座標可用。
22. **固定其他幾何與取樣。** 以結果區原點為基準，右定位點為 (320,2)，排數格 (130,2)、26×14，狀態格 (278,0)、26×26；色帶首排 y=34、每格 34×26、橫距 34、排距 27，每排十格。排數 BW 一排、WB 兩排；狀態格每格 10×10、間隔 2、白 quiet zone 2，灰階 0–80 黑、176–255 白，中間拒判。Tk 單位不等於實體像素。新左定位點精確座標由本機工程量測選定，輸出前凍結為唯一 1.2 幾何；不能以「約 320」取代精確距離，也不要求使用者再決定像素。
23. **版本與交接資料。** 程式顯示契約、正式文件、圖樣／幾何表與本機可重現範例同步為 1.2；保持既有色帶顏色及一排／兩排容量規則。交接描述新舊不相容及已知遮擋限制，不宣稱定位點能偵測所有遮擋。上方定位點以下的局部色帶遮擋仍屬外部辨識責任。
24. **跨專案責任。** monitor_start 確認 Log 就緒，check_start 確認測試活動，check_finish 確認完整結果，是交接後由 KVM_Log 實作的指令職責；Log 不新增 TCP server、不修改 LabVIEW。先更新支援新舊圖樣／幾何的橋接再部署 App 是配對部署順序，不是本專案驗收必須等待 KVM 完成的條件。
25. **本專案完成條件。** 下述本機業務／磁碟／真正 App 驗證通過，且輸出契約、精確幾何及本機證據一致，即可判定本規格實作完成。KVM_Log 自行驗收辨識、壓縮、串流、Dock 恢復及上位機流程；若發現問題，以具體影格、比例與重現方式提出後續需求，不把尚未取得其回報當成本專案未完成。先前未驗收的本地 UI 暫稿不能因本規格而自動納入或視為已完成。

## Testing Decisions

1. **已確認的驗收範圍。** 依使用者最新答覆，只驗收 Log Solution 本程式能驗證的事項。採兩個既有外部行為入口：主要為輪次協調 interface／公開快照及獨立磁碟讀取；桌面部分為真正 App／Tk 操作與輸出。取消先前要求獨立 KVM consumer 回放作為本專案驗收的建議，不執行或等待另一 repo／硬體的測試。
2. **好測試的原則。** 驗證使用者操作、公開狀態、固定配置、格位結果、持久化內容及實際可見畫面，不以私有欄位、內部方法呼叫次數或實作結構當成功條件。不另抽大量純函式只為測試，沿用輪次 seam 與現有可控制來源 adapter。
3. **既有案例作法。** 沿用輪次協調的受控時鐘／來源、準備中停止／逾時交接、衝突與警報、跨輪事件隔離、公開入口保存恢復、稽核新讀取者重建，以及真正 Tk 幾何／焦點／容量測試的既有模式。更新舊測試中人工停止不交付、四種狀態、空輪自動完成及強制焦點等已被本規格取代的斷言，不能保留舊期待而削弱新行為。
4. **接受與準備時序。** 控制來源建立先阻塞、再完成或失敗，檢查接受後 PREPARING、重複開始保持同輪、baseline 完成後才 MONITORING；在監控就緒後才新增／更新來源，驗證本輪資料會被讀取。準備停止／期限到後再解除阻塞，檢查不重啟、不改原因、不覆蓋已定案結果。
5. **人工停止矩陣。** 覆蓋未有來源、部分 PASS／FAIL、TESTING／COMPLETING、混合 NOTEST／TIMEOUT、所有格位已有終局但尚有待確認等情況；停止後完整格位、既有結果不變、未完成 STOPPED、manual_stop 原因及無待確認後人工停止標記。空／缺格／重複格、錯誤位置映射均不可視為完整。
6. **衝突／警報優先序。** 人工停止前後仍有衝突或警報時 REVIEW；逐項處理／確認之前不能可交付。確認警報不自動選衝突候選，取消視窗不等於處理完成；處理後依原完成種類呈現。
7. **期限矩陣。** FCT 從接受開始到 100 秒才有活動不被 30 秒舊值鎖定；120 秒全無可信活動／結果停止、NOTEST、一次警報、REVIEW，確認且無其他事項後才本地完成。涵蓋仍在準備、部分活動、已完成結果保留、測試及整輪期限。用受控時鐘驗到期前已接受、恰好到期才讀到、到期後遲到三類，不靠實際等待兩分鐘。
8. **profile 驗證。** 載入／匯入已存目標 FCT profile 後，從本輪公開結果／期限證據確認 120 秒真的生效；現有 DFU／BT 值保持，本輪開始後修改配置不改變凍結值。不是只斷言程式預設常數。
9. **啟動失敗／復位矩陣。** 前置配置／路徑失敗不建輪且 REVIEW 可見；接受後 factory 失敗保留失敗輪。錯誤原因可讀、各開始入口被阻擋、舊完成色帶不能使狀態變可交付；關窗不解除。排除、確認、復位後 READY，舊失敗輪取消且保存，下一次明確開始得到新輪；不產生假產品結果。
10. **活動與快速結果。** 透過本程式來源 adapter、快照、事件與色帶驗證可信 TESTING／COMPLETING、直接有效 final、單一通道與多通道的差別。沒有 TESTING 仍可正常完成，NOTEST／TIMEOUT／STOPPED 不新增可信活動。這裡驗證 Log 的輸出事實，不測試橋接 check_start 的 TCP 回覆。
11. **保存／重建。** 經公開操作建立一般完成、人工停止、警報確認、取消、失敗與復位，等待既有保存後由新的磁碟讀取者重建，逐格比對狀態、輪次、來源／處置原因、待確認及本地放行語意。注入可恢復保存失敗，驗證不阻擋原交付政策、重試不漏寫不重複、關閉仍等待完整保存；舊版本資料不改寫、不假定曾有新放行語意。
12. **本程式圖樣驗證。** 六種 2×2 圖樣、排數及結果色帶與公開狀態一致；本程式自己的契約 helper 拒絕低對比、缺格及未定義圖樣。檢查真 Tk 實際繪製，不只驗常數。此項不宣稱 JetKVM 解碼、傳輸壓縮或外部辨識器已通過。
13. **真 App 幾何驗證。** 在 Tk scaling 1.0／1.5，容量 1／10／11／20 及正常容量切換下量測與擷取本機實際視窗：標題字樣移除、左點涵蓋第一格、外圍白留白、沒有 clipping／重疊、其餘固定元素不移動、一／兩排與容量外黑格正確。紀錄最終 Tk 座標與實體像素比例，不把 Tk scaling 等同 Retina 比例。
14. **真 App 操作驗證。** 用實際開始／停止／確認／復位控制及快捷鍵驗六種階段；需要時用隔離可控來源注入失敗。確認新提示與事件的繁中／英文都可讀，原有設定、保存恢復與正常關閉可用。
15. **前景與鍵盤焦點。** 以真 Log App 及本機另一個測試視窗驗指定事件後 Log 在前、鍵盤焦點不被強制移走、不永久置頂；同批事件不造成持續搶前景。這驗證本機視窗行為，不要求特定現場 ATE 程式或 KVM 自動化流程參與本專案驗收。
16. **必要回歸與證據。** 執行受影響的輪次、啟動準備、平台映射、稽核、配置、顯示契約及原生 UI 回歸；只有新增失敗或風險才擴大重跑。保留本機結果、畫面與幾何證據，將預期、實測及環境限制分開記錄；舊 1.1 的歷史 69 項通過不是本批新行為已完成的證據。
17. **外部驗收排除。** 不把 KVM_Log frame replay、JetKVM 真硬體／串流／壓縮／Dock 恢復、LabVIEW type definition／VI 或實際 ATE 全流程放進本專案通過門檻。提供足夠契約與本機輸出供對方驗收；其問題由對方回饋成具體需求後另行處理。

## Out of Scope

- 通知恢復投影集中化與歷史查詢互動生命週期重構，即原先架構候選⑤⑥。
- 全面改寫輪次／保存／清理排程、替換 Python／Tk、導入網路結果傳輸或新的測試平台格式。
- 在 Log Solution 新增 check_start／check_finish、TCP server、LabVIEW 指令、結果 ACK／重傳資料庫或 KVM 連線／辨識實作。
- 設計 KVM_Log 完整 JSON 欄位、TCP 版本、舊 check 遷移及 LabVIEW typedef／VI；這些交由該專案接續。
- 自動重測、自動重啟 ATE、操作治具、推測物料就緒或由 Log 自行決定整批重工範圍。
- 清空人工停止的既有結果、把 STOPPED 轉 FAIL、將啟動失敗生造為產品 FAIL、人工強制採用未知同輪資料。
- 追捕正常完成後遲到檔案、放寬未知來源證據、變更既有資料保護／封存時間／正常關閉完整保存規則。
- 修改既有歷史資料來假造新契約語意，或默默採納先前未驗收的本機 UI 暫稿。
- KVM_Log、JetKVM、LabVIEW 及現場 ATE 自動化的驗收；它們不阻擋本專案依本機可驗證項目完成。
