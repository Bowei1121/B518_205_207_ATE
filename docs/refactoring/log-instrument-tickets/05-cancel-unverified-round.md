## What to build

操作員面對需人工核對的準備中停止／逾時，能在本程式確認必要事項、取消該輪並保留原結果，排除問題後明確開始新輪，沒有強制交付或自動重測捷徑。

擴充LI3失敗輪次取消能力到LI2人工停止與LI4準備逾時的本地操作路徑；不讓Log推測橋接有沒有看見MONITORING，不新增TCP、KVM輪次或遠端取消命令。

主責使用者故事：36, 66。
依父規格實作決策：4, 7, 17, 18, 19；測試決策：5, 6, 9, 11, 14。

本票只驗收本程式的公開輪次行為／磁碟資料與必要真App／Tk輸出；不要求KVM_Log、JetKVM或LabVIEW驗收。

## Acceptance criteria

- [ ] 以準備中人工停止及準備逾時實際路徑展示本地取消／復位入口，處理既有必要待確認後由操作員明確取消，不以關閉視窗或換配置默認取消。
- [ ] 取消保留原逐格結果、來源、停止／期限／警報原因及處理紀錄；不抹除、不覆寫、不把取消或軟體故障轉產品FAIL。
- [ ] 不提供強制把不確定畫面當成本輪結果交付的按鈕；取消不等於替衝突選結果或確認未知同輪候選，既有證據及資料保護政策保持。
- [ ] 取消結束後本地回可接受新輪的狀態；舊色帶即使保留也不帶可交付本輪資格，下一次明確開始產生新本地輪次、固定新配置並重新準備。
- [ ] 舊準備工作、事件與保存回覆不能覆蓋新輪；重複取消／復位不重複定案，未保存輪仍依原政策追蹤。
- [ ] 操作員決定重工範圍，Log不自動重測、不啟動ATE／治具，也不建立橋接／LabVIEW的輪次ID或ACK資料庫。
- [ ] 由新讀取者可重建取消及後續新輪的獨立紀錄；已可靠保存的其他輪次不因本操作被一律刪除或禁止查核。
- [ ] 公開入口及真App完成「準備中停止→必要確認→取消→新輪」及「準備逾時→警報確認→取消→新輪」；啟動故障復位路徑沿用LI3並做組合回歸。
