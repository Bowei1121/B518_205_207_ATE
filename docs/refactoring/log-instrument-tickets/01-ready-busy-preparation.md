## Acceptance criteria

- [ ] 按鈕、視窗內／全域快捷鍵與核心入口共用接受／鎖定規則；接受時凍結容量、映射、來源與期限，重複開始不建新輪、不清結果、不重設計時。
- [ ] 接受後立即 PREPARING／BUSY，來源仍在背景準備且視窗可操作；舊檔基準及必要準備完成後才 MONITORING，不能提前宣告可開測。
- [ ] 以可阻塞來源展示 PREPARING→MONITORING；監控就緒後才寫入的新資料能被收集，實際來源／顯示位置映射保持。
- [ ] 正常 READY、PREPARING、MONITORING、REVIEW 與 COMPLETE 對公開快照、HMI、標記一致；共用圖樣表定義規格六碼，人工停止圖樣在 LI2 才接上真實交付路徑。
- [ ] 衝突／警報 REVIEW 優先於完成；準備中、監控中、待確認及關閉保存中所有開始入口均不能換輪；此票不以 App 私有欄位另建一套狀態機。
- [ ] 只有可信 TESTING／COMPLETING／本輪有效測試結果作為實際通道活動；MONITORING、HID 成功或 WAITING／NOTEST／TIMEOUT／STOPPED 不單獨作開測證據。
- [ ] 快速或 final-only 來源未出現 TESTING 仍可正常完成；一格有活動不推論全通道開始。完整結果須精確涵蓋配置容量，不以空集合、缺格、重複格或錯誤映射放行。
- [ ] 同一份輪次事實更新色帶與狀態格；READY 保留前輪結果到下一輪開始，容量外固定黑色、排數意義與現有色碼保持。
- [ ] 正常輪次的 Session／audit 可由新讀取者重建並與公開結果一致，既有雙語事件、事件身分及保存政策不退化。
- [ ] 以既有輪次公開入口及真正 Tk／App 驗證狀態、開始控制、可信活動與正常完成，不以假 root 代替可見畫面；此票成果為整合候選，不能宣稱整套1.2已可發布。
