## 依賴理由

- LI1先提供真實準備／監控就緒及共用狀態觀察；LI2、LI3、LI4分別以此延伸停止、故障及期限路徑，三者不因同檔而互相假設前置。
- LI5需展示人工停止、準備逾時及故障復位後的完整取消／新輪操作，故依LI2／LI3／LI4。
- LI6須驗人工停止完成與正常開始／結果的前景時機，依LI2即可（LI1已為其祖先），不額外依賴故障／期限票。
- LI7是獨立顯示幾何切片，不以其他業務功能作假前置；六狀態及全部生命週期與新幾何共同驗收交LI8。
- LI8依LI5／LI6／LI7；經祖先關係已涵蓋LI1–LI4，不重複列傳遞前置。

## 整合與驗收限制

- 初始frontier為LI1與LI7；票無依賴代表語意上可開始，不代表共享Tk主檔可不協調同時修改。實作者須隔離工作並安排正常整合，不覆寫現有UI暫稿。
- 各票都須有自己能通過、可重現的展示／驗證；LI8不替前票補基本完成條件。功能途中使用同一候選整合路徑；未集成業務、完整圖樣與最終幾何前，不單獨對外宣稱或部署完整1.2。
- 所有驗收限本程式可驗證事項；KVM回放／辨識／傳輸、JetKVM、Dock自動化、LabVIEW與現場ATE流程不列前置。
- 故障復位中對失敗輪的取消由LI3完成；LI5擴充到其他需人工核對的停止／期限路徑。保存與磁碟重建隨各票行為交付，沒有另拆成橫向「最後才補保存」票。
- 核可後，依前置順序發布八個子議題、設ready-for-agent及GitHub原生子議題／阻擋關係；不編輯父規格正文或狀態，不自動認領、實作或關閉任何票。
