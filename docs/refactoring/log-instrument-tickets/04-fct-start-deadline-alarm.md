## Acceptance criteria

- [ ] 目標已存／匯入且實際選取的FCT profile確實採start=120秒；不只改新建預設，DFU／BT既有值保持，開始後修改設定不改本輪凍結期限。
- [ ] 從接受開始監控計時、包含來源準備，不於MONITORING才重設；100秒才有可信活動不受舊30秒鎖定。
- [ ] 開始期限到整輪仍無可信活動也無有效結果，停止收集、全部未開始格NOTEST，建立一次「未偵測到測試開始」警報與REVIEW，不自稱已證明ATE當機。
- [ ] 準備工作仍阻塞時也於開始期限裁決，不能等到更長整輪上限才處理；後續來源成功／失敗不重新開始或覆寫已定案格位／原因。
- [ ] 人員關閉警報視窗不等於確認；警報可確認時機須維持結果及停止一致性，人工確認且無其他待確認才本地COMPLETE／READY，不自動裁決其他衝突。
- [ ] 部分位置已有可信活動或結果時不套用整輪完全無開始警報；其餘未開始格、測試期限及整輪上限依既有規則，已定案結果保留。
- [ ] 到期限的該次輪詢先判deadline再讀來源；覆蓋期限前已接受、恰好到期才讀到、到期後遲到三類，不用來源自報時間挽回。
- [ ] 事件及新讀取者重建保留期限、停止、警報與確認事實及雙語說明，結果可交付與保存成功分離。
- [ ] 由受控時鐘與可阻塞來源及真正App警報操作驗證，不用真等120秒；未見監控就緒而需人工核對的橋接行為不列本票驗收。
