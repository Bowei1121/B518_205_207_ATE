## Acceptance criteria

- [ ] 保留既有 PASS／FAIL／NOTEST／TIMEOUT 等終局值，只把未完成格定案為 STOPPED；通道文字與灰色色帶一致，不清空整輪、不轉成 FAIL、不替操作員決定重工範圍。
- [ ] 來源尚未建立時停止也按固定配置立即產生完整格位，不等 factory 返回才呈現；配置容量與非恆等映射下結果均正確，空／缺格／重複格不得可交付。
- [ ] 停止後延遲來源成功或失敗均不能重啟本輪、改掉 manual_stop 原因、覆蓋已定案格位或將輪次偽裝為啟動失敗。
- [ ] 保留整輪人工停止種類，即使停止當下所有格位都已有終局且沒有 STOPPED 格，也不以顏色推測停止原因。
- [ ] 仍有衝突／未確認警報時保持 REVIEW，不提前放行；處理既有可信衝突及警報後才 MANUAL_STOP_COMPLETE／READY，標記0011與公開結果一致。
- [ ] 一般完成與人工停止的可交付判定都驗容量完整及無待確認；結果放行不以 Session／audit／封存成功作新前置。
- [ ] 重複停止或重複已完成處理不重複定案／寫入；保留未知同輪來源原處置，不開放採用未知候選。
- [ ] 透過公開停止、裁決與確認操作形成紀錄；新的磁碟讀取者能重建逐格狀態、manual_stop及交付種類，不假造一般finished、不重寫1.1歷史資料或推定其曾交付。
- [ ] 保存失敗可見且可恢復、重試不漏寫不重複，仍完整保存才正常關閉；原雙語與資料保護規則保持。
- [ ] 以正常監控、準備阻塞、混合終局、所有格位終局但仍待確認等情境做公開入口及真正App驗證；尚未定稿幾何不妨礙本機展示此停止路徑。
