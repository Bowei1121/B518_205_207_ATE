## What to build

查閱中的固定結果不阻擋保存與期限清理；可信暫存快照中的原內容即使來源已刪除或替換仍可讀，不冒充新版本，也不混入新內容。

## Acceptance criteria

- [x] 正式保存新增事件不自動改動目前集合，再次查詢才更新；查詢只是已保存來源的視圖，不要求監控writer額外flush。
- [x] 可信 H3 暫存中的完整原始 JSON 視為已取得，即使尚未點選，正式清理後仍可讀；同路徑替換不會以新內容冒充舊事件。重新查詢才反映當前來源集合。來源版本在讀取期間變動則標為未確認。
- [x] 來源版本被替換且原版無法取得時同樣不得把新內容當舊固定結果；查詢讀取期間變動需驗證或標示未確認，不要求跨來源交易鎖。
- [x] 查詢視窗不延後合法清理；來源刪除讓衍生索引失效，不改ledger、保存期限、可信封存起算或待確認／未保存保護。
- [x] 以正式保存／清理公開入口、真實磁碟與全新讀取器驗證競態及契約一致，真正 Tk 驗證固定列、有效選取、已取得內容、切語與重查。現行 H3 的有效固定列均有可靠完整原始 JSON 快照，因此「原內容尚未取得的固定列在來源消失後提示不可取得」條件不適用，未宣稱測到此不存在的情境；適用前提見下方釐清。
- [x] 維持ADR0007／0008／0009：監控結果、裁決、雙語同筆、保存成功才關閉及原始bytes契約不因查詢而改變。

- [x] 必要測試、真正桌面驗證、完整含 Tk 套件及固定基準雙軸審查通過：Python 3.8.10/Tk 8.6.8 最後程式／測試版 `897f6f2` 完整 461 tests / 139.240 sec / exit 0 / no skips。先前原生 `Tcl_AsyncDelete` 已用固定基準重現，定位到 M10 測試故障注入 traceback 循環，修正主執行緒測試收尾後重驗通過；詳見 H6 evidence。工廠驗收另追蹤，不修改原始紀錄、監控裁決或保存／清理契約。

### 已取得內容與提示條件的適用前提

2026-10-14 使用者明確釐清：「可信暫存內容算已取得，來源清理後仍可讀」。H3 在發布任何有效固定列之前，已把該列的完整原始 `event_json`（身分、原文、詳細、診斷與來源定位）存入查詢所屬的可靠磁碟暫存；「按需詳細」指點選後才讀取／反序列化／呈現快照，不表示尚未捕捉原始內容。因此未點選列在正式清理後仍屬已取得內容，不應改顯示不可取得。

母規格「尚未取得來源消失時在原事件位置提示不可取得」是一個條件式要求；現行 H3 完整快照契約下，沒有原內容尚未捕捉卻已發布的有效固定列，所以此條件在本交付不適用。如果捕捉期間來源消失或版本未確認，則不發布該來源的正常列，沿用公開不完整結果／來源診斷；不製造事件身分或以其他事件補位。H5 的快照／頁面／詳細 I/O 失敗處理保持。沒有為測出提示而破壞 H3 快照、刪除查詢暫存或將已取得內容偽稱未取得。
