# H8：大量資料驗收與舊流程收尾

## Parent

規格：[GitHub #37](https://github.com/Bowei1121/B518_205_207_ATE/issues/37)。

## What to build

完成整體日期查詢、背景工作、分頁與索引的可重現容量驗收，移除舊全量桌面入口，交付可合併的完整功能及獨立現場驗收清單。

## Acceptance criteria

- [x] 全規格故事與測試矩陣逐項對照最終程式，舊重新整理／開視窗／語言刷新不再繞過條件走全量桌面讀取；必要產品回歸及真正Tk驗證通過。
- [x] 至少5萬筆參考集與216萬筆合成事件集，含輪次／App及日期內外；明列來源數、大小、事件比例與runtime，不把產量當實測事件量。
- [x] 每個成本情境至少三次相同fixture，分開報告首次索引、正常重查、單來源變更、降級、換頁；揭露冷暖條件、耗時、讀取bytes、完整解析來源數、記憶體峰值及存活worker。
- [x] 正常重查／換頁不反覆全量解析，單來源變動不使其他未變更來源全重讀；來源原檔基準比對日期／身分一致。完整詳細不全量駐留，取消／重查／關閉後worker與資源不持續累積。
- [x] 受控慢讀阻擋期間實際完成Tk編輯、取消或重查，容量測試附畫面回應間隔；不只檢查函式呼叫或宣稱背景thread存在。
- [x] 逐票開發驗證與最後整體驗證均可合併，不把工廠資料取得／設備效能／正式部署作阻擋條件；另列現場工時、事件比例、三個月存量與設備效能驗收，不宣稱已完成。

- [x] 完成此票必要測試、真正桌面驗證及相關回歸後可合併；工廠驗收另追蹤，不阻擋合併。不修改原始紀錄、監控裁決或保存／清理契約。
