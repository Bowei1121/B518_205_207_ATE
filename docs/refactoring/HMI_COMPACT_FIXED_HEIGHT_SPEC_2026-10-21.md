# 規格：固定高度 HMI、緊湊通道表格與白話操作提示

## Problem Statement

操作員目前只能在占用較大高度的表格內看到少數通道；列內留白過多、橫向分隔線不明顯，表格與開始監控按鈕之間又有大塊空白。兩個平常不能使用的異常處理按鈕持續占用主畫面，文字也難以直接理解。

App 高度會隨測試容量改變，不利於固定位置操作，以及橋接程式建立計時區影像模板。將異常操作移到鈴鐺後，也必須讓操作員清楚知道還有什麼事要處理，避免只看到開始按鈕不能按。現有部分按鈕提示包含技術詞彙，需要改成操作員看得懂且不會誤解操作結果的中英文。

## Solution

App 啟動時依螢幕可用空間決定一次高度，之後固定。縮小通道列的上下留白，保留文字大小，取消文字表格最多顯示十列的限制；空間足夠就顯示更多，放不下才捲動。內部橫線與直線統一使用清楚的黑色分隔線，表格外框與開始按鈕之間只留小間距。

表格可視區、開始按鈕、狀態與計時位置固定；通道少時在表格內留背景，不收縮視窗，也不虛構額外通道。兩個異常處理操作移入鈴鐺，有待處理事項時以一致件數及每秒亮暗切換的紅字提醒，全部處理完成才停閃。所有主頁與子視窗按鈕提示及停用原因，依「先說按了做什麼，再說必要結果」的原則同步整理繁體中文與英文。

## User Stories

1. 身為操作員，我希望開啟 App 後視窗高度固定，以便每次在熟悉的位置操作。
2. 身為操作員，我希望不同螢幕可在啟動時使用適合的高度，以便操作區完整留在可用畫面內。
3. 身為操作員，我希望切換測試配置不改變視窗高度，以便不必重新尋找按鈕。
4. 身為操作員，我希望視窗不能手動拉伸，以便避免誤操作改變布局。
5. 身為操作員，我希望通道列只保留文字需要的高度與少量上下間距，以便一次看到更多通道。
6. 身為操作員，我希望列高縮小時保留字體大小，以便仍能清楚閱讀。
7. 身為操作員，我希望空間足夠時可以同時看到超過十個通道，以便減少捲動。
8. 身為操作員，我希望空間不足時能捲動到最後一個通道，以便不漏看任何配置位置。
9. 身為操作員，我希望上下邊界顯示完整列，以便不把被裁切的文字看成遺漏資料。
10. 身為操作員，我希望通道全部可見時捲軸維持原位且停用，以便布局不跳動。
11. 身為操作員，我希望表格內橫線與直線都是黑色，以便清楚區分每個通道與欄位。
12. 身為操作員，我希望黑線不改變狀態顏色，以便沿用既有判讀方式。
13. 身為操作員，我希望表格與開始按鈕之間的多餘空白縮減，以便畫面更緊湊。
14. 身為操作員，我希望通道較少時只在表格內留白，以便操作區位置固定。
15. 身為操作員，我希望留白不被畫成額外 Slot，以便不誤認設備容量。
16. 身為操作員，我希望開始按鈕、監控狀態與計時保持固定位置，以便不因容量或通知改變而找錯位置。
17. 身為橋接維護者，我希望相同設備與顯示條件重開 App 時布局穩定，以便重用已建立的影像模板。
18. 身為橋接維護者，我希望中英文切換與長狀態不移動或遮住計時，以便持續讀取相同區域。
19. 身為操作員，我希望主畫面移除平時不能使用的異常處理按鈕，以便集中注意日常操作。
20. 身為操作員，我希望從鈴鐺查看啟動異常原因並執行解除操作，以便排除問題後重新開始。
21. 身為操作員，我希望解除啟動異常後不會自動重試或開測，以便由人員明確決定下一步。
22. 身為操作員，我希望從鈴鐺取消無法確認的這輪並保留紀錄，以便放棄交付而不丟失證據。
23. 身為操作員，我希望取消前仍需明確確認，以便避免誤取消。
24. 身為操作員，我希望不符合操作條件時能看到不能按的原因，以便知道還需要處理什麼。
25. 身為操作員，我希望有啟動異常、待取消輪次、未確認警報或保存／封存失敗時看到紅字提醒，以便及時處理。

27. 身為操作員，我希望同一件異常不因多個顯示入口重複計數，以便件數反映實際待處理事項。

29. 身為操作員，我希望開啟或關閉鈴鐺不會讓提醒消失，以便不把查看誤認成處理完成。

32. 身為操作員，我希望提示閃爍、出現或消失不推動其他元件，以便按鈕與計時位置穩定。
33. 身為操作員，我希望結果衝突仍使用原本的警告入口，以便不混淆不同處理流程。
34. 身為操作員，我希望主畫面每個按鈕提示都用白話解釋操作效果，以便不用猜術語。
35. 身為操作員，我希望各子視窗及新搬入鈴鐺的按鈕也有一致提示，以便進入其他畫面後仍能理解。
36. 身為操作員，我希望繁中與英文提示意思一致，以便切換語言不改變對操作的理解。
37. 身為操作員，我希望按鈕不能使用時提示原因，以便知道如何完成必要處理。
38. 身為操作員，我希望滑鼠停留或鍵盤焦點只顯示說明、不執行動作，以便能放心查看提示。
39. 身為操作員，我希望切換語言時已開視窗與提示一起更新，以便不混用不同語言。
40. 身為操作員，我希望提示區不遮住計時、結果及必要操作，以便同時判讀畫面。
41. 身為橋接維護者，我希望取得改版後實測計時裁切區與顯示條件，以便更新模板而不沿用舊座標。
42. 身為橋接維護者，我希望紅字閃爍與 App 畫面心跳互相獨立，以便通知變化不干擾活性判斷。
43. 身為操作員，我希望搬移按鈕不改變警報確認、保存重試及結果交付條件，以便沿用既有處理規則。
44. 身為維護者，我希望關窗後不留下閃爍或提示工作，以便重開視窗不出現重複回呼與錯誤。
45. 身為驗收者，我希望本機布局證據與真實 JetKVM 接收影像證據分開記錄，以便知道哪些環節已驗證、哪些仍待設備驗收。

## Implementation Decisions

### D1. 啟動時決定固定幾何

- 沿用桌面介面與既有視窗管理，依啟動時螢幕可用區域、既有文字大小及必要控制項需求決定高度；不以目前測試容量參與高度選擇。同設備與相同顯示條件須得到穩定幾何。
- 高度選定後不隨容量、語言、輪次狀態、通知數量或提示有無改變，不允許手動拉伸；沿用既有固定寬度。必要內容的排版與長文字顯示須在此限制內驗收。
- 不直接把螢幕全高當內容可用高；需考慮視窗裝飾及系統保留區。最終目標高度與適用的最小螢幕條件以量測交付，不在規格捏造數值。
- 表格可視區、開始按鈕、狀態、計時及通知提示區保持固定布局；不同容量的上方結果色帶不得間接推動這些區域。沿用既有 KVM 固定定位點、結果排列及容量規則，不藉此改結果色帶規格。

### D2. 緊湊表格與間距

- 每列保留既有主畫面字體大小及狀態文字可讀性，以實際字體所需高度加少量上下間距決定一致列高。字體不因文字、SN、容量或剩餘空間自動縮小。
- 取消文字表格十列上限，從固定可視區與完整列高計算可見列數；顯示最多為當前測試容量，內容不足時保留背景，不新增假 Slot。
- 放不下時沿用既有捲動操作，最後一列必須完整可達；內容全可見時捲軸原位停用。不得保留另一條隱藏的十列限制。
- 表格內部橫向及縱向分隔線均為清楚的黑色，保留既有欄位、狀態顏色與 SN 資料顯示語意。線寬由不同縮放的實測決定。
- 表格外框至開始按鈕間只留小間距，對照相同顯示條件的改版前畫面，將多餘空白朝減少約一半的目標調整並交付前後量測。這是布局目標，不得為追求比例裁切必要內容；表格內少量通道的留白不算此多餘間距。

### D3. 鈴鐺操作入口

- 使用既有通知與恢復中心，收納解除啟動異常及取消未確認輪次操作，移除兩個主畫面操作元件的占位；保留主畫面日常開始、停止及既有保存操作。
- 新入口顯示對應原因、可操作條件及停用原因，沿用既有操作協調與公開入口，不另建故障解除、輪次取消或保存狀態機。
- 解除啟動異常維持：人員排除及確認後才解除開始鎖定；不自動重試、不啟動 ATE。有輪次與無輪次失敗仍依原規則處理及保留紀錄。
- 取消未確認輪次維持明確確認步驟，放棄本輪交付並保留結果與處理紀錄；取消確認視窗本身不改變輪次。不能繞過未完成的準備、必要警報確認或結果衝突，也不提供強制交付捷徑。
- 鈴鐺仍可在零事項時開啟；查看或關閉中心不視為已確認或已解決。

### D4. 一致件數與紅字閃爍

- 沿用既有通知來源並納入啟動異常與待取消輪次，涵蓋未確認整輪警報、保存失敗與封存失敗。鈴鐺與主畫面從同一份實際待處理事項清單取得件數，不各自推算。
- 同一事項有多個原因說明或操作入口時不重複計入；不同輪次或不同獨立未解問題仍須保留。結果衝突維持獨立警告入口及計數，不混入鈴鐺。
- N 大於零時，以目前語言顯示「有 N 件事需要處理，請點鈴鐺」及等義英文。紅字每一秒切換亮／暗一次；以固定占位改變可見性，不反覆移除布局元件。
- 開啟鈴鐺、切換分頁或語言、隱藏再顯示恢復中心，不會清零或停止提醒。依真實處理結果更新件數；處理失敗仍保留，全部解決後才停閃並隱藏文字，提示區保持占位。
- 使用既有受管理的畫面計時生命週期，避免重複建立閃爍工作；關窗時取消。通知更新與閃爍不得修改輪次紀錄、監控經過時間、KVM 狀態或獨立心跳節拍。

### D5. 白話中英文提示

- 沿用既有語言資源、停留／焦點提示與鍵盤操作方式，整理主頁、設定、通知與恢復、待確認、歷史查詢、診斷及其現有子視窗的按鈕提示與停用原因。包含新搬移的兩個操作。
- 繁體中文與 English 同步；先講操作，再講重要效果或不能按的原因。必要領域詞彙保留，但避免只用「復位」「封存」「未驗證輪次」等術語代替說明。
- 白話化不得改變操作意義：開始監控不等於啟動測試設備；解除異常不會自動重試；取消這輪不刪紀錄，也不代表產品 FAIL；停止與取消不可寫成同一操作。
- 延續既有即時語言刷新、停用控制提示、鍵盤焦點及關窗清理，不因查看說明觸發操作。範圍以提示及停用原因為主，不擴大成全介面重新命名。

### D6. 顯示契約及既有流程

- 遵守 ADR 0010～0013：監控經過時間增加僅輔助表示開始流程已受理，不替代監控就緒、可信測試開始或結果可交付證據；獨立畫面心跳繼續保有原本用途。
- 現有 App 端本機顯示契約為 1.3；改版須重新量測幾何與計時裁切區，記錄契約相容性及橋接交接，不得將舊裁切座標標成新畫面可直接沿用。若不相容，依既有契約版本管理規則處理。
- 不改來源解析、結果裁決、保存完整性、稽核紀錄或資料結構；不新增 TCP 命令與遠端取消協定。橋接程式由其所屬專案依交接另行配對。

## Testing Decisions

### 已確認的驗收入口

使用者已確認以下三組範圍，以實際 App 操作為主要驗收入口，優先擴充現有測試與影像工具，不新建一套平行驗收框架。

1. **App 畫面與操作**：實際開啟 App、選配置、切語言、捲動及查看提示，驗證可見結果與元件幾何。
2. **異常處理到紀錄保存**：由既有配置／來源／保存失敗情境產生真實待處理事項，從鈴鐺操作，核對鎖定、件數、閃爍與持久化紀錄；不只檢查函式被呼叫。
3. **顯示影像與橋接交接**：沿用既有本機 Tk／原生截圖與 KVM 幾何矩陣，補上改版裁切區；真實 JetKVM 接收端另外核對畫面可讀性與模板。

測試只斷言使用者或橋接可觀察的行為，不綁元件私有名稱、排版實作或內部計時器數量。必要純邏輯邊界可沿用既有測試，但不可替代真 App 操作與影像證據。

### 既有先例與覆蓋模組

- 桌面布局沿用 Slot 表格可視範圍驗收、主畫面固定幾何、不同容量與雙縮放矩陣，以及真 Tk 計時與長分鐘顯示案例；舊十列上限斷言須依本規格更新，不能保留為新需求的阻擋。
- 異常與紀錄沿用真 App 的來源準備失敗、啟動異常解除、準備中停止／逾時後取消、警報人工確認及恢復中心保存重試案例。
- 提示與多語沿用主頁／設定／恢復／歷史／診斷的雙語提示、鍵盤焦點、語言刷新及生命週期測試。
- 影像沿用現有計時裁切矩陣、定位點與結果色帶幾何證據，以及獨立心跳驗收；通知閃爍不可被當作心跳正常的證據。

| T12 | 持續待處理並觀察紅字 | 每秒亮暗切換，提示區、按鈕、狀態與計時幾何不變；長件數及英文完整可讀 |
| T13 | 開啟／關閉中心、切分頁或語言 | 不清零、不停止未解事項提醒；不觸發解除、確認、取消或重試 |
| T14 | 部分解決、操作失敗、全部解決 | 部分解決減少件數且仍閃；失敗仍提醒；全部解決才停閃隱藏字，保留占位；新事項再次出現能恢復提醒 |
| T15 | 單獨結果衝突及與鈴鐺事項並存 | 原警告入口及裁決流程維持，不混算兩入口數字、不繞過結果放行條件 |
| T16 | 逐視窗查看可用／停用按鈕提示 | 中英文與實際動作一致，涵蓋新增入口及停用原因，停留／焦點不執行操作 |
| T17 | 提示顯示時切語言、換焦點及關窗 | 說明更新至目前語言，無失效提示殘留，不遮住必要辨識區 |
| T18 | 通知持續閃爍，計時超過 99 分鐘及長狀態 | 計時完整、位置穩定、閃爍與心跳互不影響；監控停止後耗時仍按原規則保留 |
| T19 | 通知未解時關閉／重開中心，正常關閉 App | 不重複閃爍、不留下失效回呼；既有保存失敗與取消關閉流程保持可操作 |
| T20 | 從異常處理到保存後重新讀取紀錄 | 原因、結果及處置保留，不因搬移入口或通知更新重複寫入／遺失，也不把取消變產品 FAIL |
| T21 | 改版後本機幾何及原生影像矩陣 | 交付容量、語言、縮放、固定高度、計時範圍、狀態／心跳與定位點幾何及相容性說明 |
| T22 | 真實 JetKVM 接收畫面及更新模板 | 另行確認實際縮放／壓縮下可讀性、裁切區與模板；無設備時明列待驗，不能以 T21 冒充通過 |

量測與真 App 驗收須記錄確切提交、執行環境、跳過項目及證據來源。本次產出規格不等於已執行上述測試。

## Out of Scope

- 不實作橋接端辨識、TCP／LabVIEW／Dock 自動操作、ATE 開測控制或新增遠端命令。
- 不改監控來源、產品結果判定、輪次語意、人工裁決、紀錄保存期限及結果可交付條件。
- 不新增通知聲音、強制採用不確定結果、自動重試／重測或點開就自動確認。
- 不新增語言、不重寫全部畫面名稱與歷史事件原文、不更換 UI 框架或重做整體品牌樣式。
- 不把本規格直接展開為產品實作、開發子票、PR、自動合併或既有議題結票。
