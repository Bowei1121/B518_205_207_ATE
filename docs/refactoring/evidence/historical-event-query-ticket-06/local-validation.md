2. **Captured details survive official deletion:** The AppEventStore and RoundCoordinator cleanup cases verify that detail selected before cleanup and detail first requested after cleanup both return the original captured raw JSON. The event key and old page remain fixed. This follows the clarified contract that H3's trusted complete temporary JSON snapshot is already acquired content. The Tk case selects a previously unselected event after cleanup, reads its original raw diagnostic, switches language, and preserves the selected key and content.
3. **Same-path replacement and in-flight mutation:** An official AppEventStore atomic journal rewrite after snapshot leaves its old page and old unselected detail unchanged; the added record appears only after a new query. The frozen result contains the old raw diagnostic and never contains replacement detail. Separate Event-controlled disk tests replace a source during fallback read and add a source during indexed and fallback reads. Affected records are withheld from a complete-looking result and a source warning retains the path. No transaction lock is held across sources.
4. **Retention and derivative index:** Official App journal cleanup finishes while the result is open. The analogous RoundCoordinator retention case deletes an archived source while the query remains open; cleanup is complete, the old fixed page and captured details do not change, and the query does not pin source files. A new service/query no longer returns deleted rows and invalidates the derivative source. Tests inspect cleanup status/summary and protected ledger/source bytes; H6 never edits the ledger, expiry, archive timestamp, retirement sequence, or protection policy.
5. **Official disk and Tk routes:** The App test uses a real Tk interpreter/widget interactions, actual temporary journal/index files, the public AppEventStore save/retention path and public history Search. `tests/test_round_retention.py` uses real archived disk state, official retention, an index, a fresh coordinator/reader and public query. Sources and external protection fixtures are isolated under temporary App roots.
6. **Existing product contracts:** H6 changes only derivative index format and historical presentation. It does not change monitoring, adjudication, alarms, save format, retention deadlines, archive rules, KVM, writer policy, or raw-source bytes through query. Existing regression modules remain in the complete-suite command. H6 string uses centralized EN/zh-TW resources and the existing App-language refresh callback.
