## Index validity and commit rules

The v1 SQLite file is a disposable cache, not an audit source. It is stored outside `session_root`; it does not rewrite or participate in deletion eligibility for audit files, old event logs, or the App journal. The version tuple includes device, inode, size, modification time and change time. This detects same-size content replacement with a restored mtime on the tested filesystem without hashing and fully rereading every source on each query. Directory discovery and version stat checks still happen on a query; they are not claimed to be zero-cost.

For each source, the reader must complete, the source version before and after the read must match, parsing and integrity checks must succeed, and the index transaction must commit before the source record is reusable. On version mismatch, addition, move, deletion, or a changed source, affected records are refreshed/removed. An uncertain or failed read does not become a successful cached-empty source. A refresh cancelled before commit rolls back. A scan race returns an incomplete diagnostic and remains eligible for retry. Existing source priority and identity de-duplication are applied while creating query records. Date selection reuses H1's semantics: offset-bearing timestamps are converted using the submitted local timezone; naive legacy times are interpreted as local wall time. The index stores enough time information to reinterpret aware timestamps for a new query timezone, rather than freezing the index-creation zone or round date.
