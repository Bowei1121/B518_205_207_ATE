# 通用 Log 監控工具模組化提案

狀態：供訪談確認的提案，未授權開始實作。依據為截至 2026-09-29 第九輪問答；已接受的規則以訪談摘要及 ADR 為準，以下拆分與遷移順序尚待確認。

## 重構成功的可觀察結果

- 已支援的平台修改容量、路徑、位置對應、逾時，只需在進階畫面修改並匯出配置，部署時不重打包 App。
- 新增 Log 格式時，開發集中於該平台模組、樣本與測試、註冊及打包；不需要逐一修改 UI、KVM 排列與共同逾時規則。
- 核心可以使用樣本 Log 與可控制的時間重現監控行為，不必開啟 Tk 畫面或等待真實測試儀器。
- 能從紀錄查到本輪配置版本、通道來源、狀態變更、逾時原因與人工選擇。原始 Log 是否納入診斷包另定，不假定現有 Session 已備份原始檔。

## 四個主要 Module

| Module | 對外 Interface 與責任 | 內部 Implementation |
| --- | --- | --- |
| 測試配置 | 列出專案／機型、驗證／匯入／匯出配置、取得本輪配置快照 | 配置版本、平台參數、路徑、容量與位置對應、逾時合法性；不解析測試結果 |
| 平台資料來源 | 準備本輪來源、讀取新的觀察資料、停止收集 | Atlas、B482 BT、RS-WMT 各自作為 Adapter；封裝檔案探索、增量讀取、日期、格式、檔案穩定性與平台特有證據 |
| 監控輪次 | 開始／停止、提交人工選擇、取得一致的輪次狀態 | 各通道狀態、開始與測試逾時、整輪上限、候選結果衝突、待確認與完成規則；背景排程、時鐘與紀錄寫入經內部 Seam 注入 |
| 桌面介面 | 將操作交給配置或輪次 Module，呈現一致狀態 | 專案＋機型選擇、工程師進階編輯、KVM 十格／兩排、黑白狀態標記、可捲動明細、人工確認與快捷鍵 |

Module 的 Interface 同時供 UI 與測試使用。UI 不直接讀寫具體監控器內部 results，也不依平台名稱自行判斷 SN 或 NOTEST。不為每個小函式製作只轉呼叫的包裝層。

## 平台與共同規則的 Seam

平台 Adapter 輸出來源觀察與候選結果，附來源檔案、來源時間、位置、SN、結果及可取得的批次證據。共同輪次 Module 負責時間與生命週期，平台格式判讀留在 Adapter。

現有平台的語意差異不能因抽象化而消失：B482 明確空 SN FAILED 與 RS-WMT 無 SN Fail 不等價；同樣沒有 Log，也不能由解析器假定治具實際為空。由共同規則在等待期限到達後產生的 NOTEST，需與平台明確回報的 NOTEST 在內部原因與紀錄中區分。

來源能否判定同輪，由 Adapter 提供證據；來源不確定時是否允許人工覆蓋，是使用者保留的業務決策，不在本提案中默認允許或禁止。內部事件須能識別其所屬監控實例，避免 UI 把舊實例事件套到新實例；這項技術隔離不等於替使用者決定可疑來源的人工採用政策。

## 監控結束與結果取用

收集是否停止與結果是否可取用分開表示。全部通道有結果即停止讀檔；有未決衝突仍顯示待確認。整輪上限到達亦停止讀檔，保留結果、未開始者 NOTEST、已開始未完成者 TIMEOUT，新增一次待確認警報。所有必要人工確認完成後才呈現本輪完成。

同一狀態快照供畫面、KVM 標記與紀錄使用，避免三處各自推算不同結果。不得由「監控執行緒已停止」直接推定「上位機可取用」。

## 建議遷移順序

1. 保留現行可用版本，建立既有格式的特徵測試與樣本回放基準；現場尚未驗證的平台限制繼續列明。
2. 先抽出配置與平台資料來源，透過相同測試入口確認既有資料仍可正確辨識。來源編號的硬編碼必須與位置對應一起整理，不只修改畫面列數。
3. 抽出共同輪次規則，加入配置容量、開始等待 NOTEST、整輪上限與人工確認生命週期；用模擬時間驗證，不以長時間等待測試。
4. 接上配置編輯／匯入匯出、新 KVM 排列、狀態標記與可捲動明細；同步定義上位機取用契約。
5. 驗證 App 與上位機組合，再完成既有 macOS 建置流程與目標機驗收。新排列不與舊上位機混用。

這是內部遷移步驟，不是承諾交付多個缺功能版本；既有 Tk 與 macOS 支援先沿用，不同時更換 UI 技術。

## 建議驗收案例

- 配置容量 4、6、10、12、20；容量內空位與容量外黑格正確區分。
- 平台已支援時只改配置即可變更路徑、位置與逾時；非法或重複位置在開始前被指出。
- 開始等待到期且完全無活動：NOTEST；已開始未完成：依通道或整輪規則 TIMEOUT；已有結果不被重置。
- 全通道結果齊全立即結束收集；有未決確認不放行，確認完才供上位機取用。
- 整輪逾時只產生一次警報，停止收集，其餘結果不變；確認警報不等同於替所有衝突自動選結果。
- 彈窗期間其他通道可繼續收集，KVM 標記不被遮住；二十筆明細捲動不移動色帶。
- 舊監控實例排隊事件不污染新實例；停止後不另開遲到檔案觀察期。
- 同 SN 同結果的重複來源、不同 SN、不同結果、來源批次不確定各自有可回放案例；不確定來源的預期處置待使用者定案。

## 尚待確認與落地限制

- 使用者是否接受以上主要 Module 分工、遷移方式與驗收方向。
- 上位機辨識程式的實作是否納入同一輪重構交付；若不納入，交付的契約與測試素材需另行約定。
- 同一專案＋機型在不同電腦採不同平台／容量時，部署配置如何避免選擇歧義。
- 配置版本更新與既有 preferences.json 遷移方式、配置匯入動作由誰執行。
- 新增整輪上限與各平台等待值，應由工程師根據測試／匯出時間設定，不把訪談中的示例秒數當正式值。
- 黑白標記與色帶的像素規格、縮放與 KVM 壓縮辨識驗證、部署作業系統驗收仍需實作階段完成。
- 來源不確定的人工採用規則明確保留；不能因此宣稱整份設計或相應驗收已完成。
