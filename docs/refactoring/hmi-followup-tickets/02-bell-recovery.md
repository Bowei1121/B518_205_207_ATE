## What to build

鈴鐺即使沒有警報仍能開啟，操作員可在其中查看並人工確認整輪警報、選輪次重試保存及執行封存重試。

## Acceptance criteria

- [ ] 提供整輪警報與保存／封存兩類資訊，零警報亦可開啟並閱讀狀態，維持本次 App 執行期間原有追蹤範圍，不掃描全部歷史 Session。
- [ ] 每項警報的識別、原因與人工確認效果保留，開窗不自動確認，確認警報不代表資料已保存。
- [ ] 可選擇本次執行期間未保存輪次並重試，保存失敗與封存失敗分開呈現，保留可理解說明與原始診斷。
- [ ] 封存重試維持原本符合資格輪次的實際範圍及啟用條件，不誤縮成只重試選取輪次；介面說明與實際操作一致。
- [ ] 本票先保留主頁既有恢復入口，避免後續精簡前失去功能；共用現有保存／封存狀態，不建立兩套相互矛盾的狀態。
- [ ] 使用真實暫存紀錄及可控寫入失敗，從新視窗完成重試，查核最後紀錄完整且無重複寫入；重試進行時介面可操作。
- [ ] 正常關閉仍等待全部應保存資料，失敗可重試或取消關閉，不能由鈴鐺開關或警報確認繞過。
- [ ] 真正 App 繁中／英文視窗均完整可讀，切語言及重新開窗保留必要選取、輸入及閱讀狀態；提供操作及畫面證據。
