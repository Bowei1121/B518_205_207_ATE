# 輪次紀錄生命週期：可復原保存、完整保存後關閉與保存期限

## Problem Statement

操作員正常關閉 App 時，目前只等待最新一輪的 Session 與 audit 各兩秒，保存失敗仍會關閉。背景 writer 會移除失敗工作，後續 flush 不會重試；開始新輪後，前輪未保存資料也缺少統一追蹤。因此「佇列已排空」不代表輪次紀錄完整保存，紀錄可能在正常關閉時遺失。

長期使用時，App 產生的輪次紀錄沒有保存期限，磁碟用量會持續增加。工程師需要可設定半年至一年等保存時長，同時避免刪除待確認、未保存完整或無法辨識的資料。audit writer 目前永久等待工作，已結束輪次會累積背景執行緒。

## Solution

提供完整的輪次紀錄生命週期：保留失敗工作供重試，追蹤本次 App 執行期間所有未保存輪次，只有必要輪次紀錄完整保存後才正常關閉；等待時視窗保持可操作，操作員可以修復問題後重試，或取消關閉。

工程師在 App 設定畫面設定全域保存天數，預設 365 天，可改為 180 天或其他正整數。保存期限從整輪結束且完整保存的封存時間起算，背景自動清理到期整輪紀錄並留下摘要；無法確認可清理條件的資料保留。穩定性與既有行為一致優先於效能數字。

## User Stories

1. As an 操作員, I want 正常關閉前完整保存輪次紀錄, so that 不會因關閉 App 遺失本輪結果與稽核證據。
2. As an 操作員, I want 關閉前同時確認 Session 與 audit, so that 單一保存成功不會被誤判為全部成功。
3. As an 操作員, I want 前一輪保存失敗後即使開始新輪仍保留待保存資料, so that 換輪不會丟失紀錄。
4. As an 操作員, I want 關閉檢查涵蓋本次 App 執行期間所有未保存輪次, so that 早於最新一輪的失敗也能被補存。
5. As an 操作員, I want 清楚看見保存失敗原因與受影響輪次, so that 能請工程師修復磁碟空間或寫入權限問題。
6. As an 操作員, I want 修復後按重試保存, so that 不必重做測試即可保存原本紀錄。
7. As an 操作員, I want 保存失敗後可取消關閉並留在 App, so that 能處理問題而不遺失未保存資料。
8. As an 操作員, I want 保存與重試期間視窗仍有回應, so that 不會把等待誤認為 App 當機。
9. As an 操作員, I want 重複按關閉或重試不產生重複保存工作, so that 不會重複寫入事件或造成並行關閉競爭。
10. As an 操作員, I want 保存成功後正常關閉, so that 過往已修復的錯誤不會永久阻止關閉。
11. As an 操作員, I want 保存狀態與產品結果放行條件分開, so that 稽核故障不擅自改變已確認的產品政策。
12. As an 操作員, I want 停止讀檔後的人工衝突處理與警報確認仍能保存, so that 完整保留最後決定。
13. As an 工程師, I want 失敗工作保持原內容與順序, so that 重試後可重建真實事件經過。
14. As an 工程師, I want 重試不漏寫、不重複寫入且可處理部分寫入, so that 磁碟稽核內容仍可靠。
15. As an 工程師, I want 保留歷史錯誤與恢復結果但分辨目前未保存狀態, so that 能追查故障且確認資料是否已恢復完整。
16. As an 工程師, I want 在 App 設定畫面修改全域保存天數, so that 可依部署需求管理磁碟用量。
17. As an 工程師, I want 預設保存 365 天且可改成 180 天或其他正整數, so that 可選擇適合的保存時長。
18. As an 工程師, I want 保存天數在重啟及其他配置儲存後維持, so that 不必每次重新設定。
19. As an 工程師, I want 無效保存天數被明確拒絕且保留原有效設定, so that 不會誤用零天、負數或無法解析的值清理資料。
20. As an 工程師, I want 保存期限從封存時間起算, so that 待確認期間不會消耗紀錄保存時長。
21. As an 工程師, I want 新期限適用所有可清理的既有輪次, so that 調整設定能真正控制現有磁碟用量。
22. As an 工程師, I want 縮短期限時看見既有紀錄可能到期的提示, so that 理解下次自動清理的影響。
23. As an 工程師, I want 到期資料按整輪清理, so that 不會只剩部分結果或失去對應稽核資料。
24. As an 工程師, I want 同輪分散於不同保存位置的紀錄一起判定, so that 早期 audit 與 Session 不會被誤認為不同輪次。
25. As an 操作員, I want 正在監控、準備中及待確認輪次不被清理, so that 正常流程與人工操作不受影響。
26. As an 工程師, I want 寫入中、保存失敗及未保存完整的輪次保留, so that 修復與重試仍有完整資料。
27. As an 工程師, I want 未知、損壞或缺少可信封存時間的資料保留, so that 不會因猜測日期誤刪紀錄。
28. As an 工程師, I want 配置、偏好、人工匯出與平台原始 Log 不受輪次清理影響, so that 保存期限只管理 App 的輪次紀錄。
29. As an 操作員, I want App 啟動後在背景檢查到期紀錄, so that 不需人工定期整理。
30. As an 操作員, I want App 長期開啟時每天檢查一次, so that 不必重啟才能清理到期資料。
31. As an 工程師, I want 修改保存期限後安排一次背景清理, so that 新設定在下一次清理生效。
32. As an 操作員, I want 清理不阻塞監控與 UI, so that 資料維護不影響測試操作。
33. As an 操作員, I want 清理工作不重疊且關閉保存期間不啟動新清理, so that 維護工作不與保存競爭。
34. As an 工程師, I want 看見清理時間、使用期限、刪除、跳過與失敗摘要, so that 能追查維護結果。
35. As an 工程師, I want 清理失敗留下摘要並在下次再試, so that 暫時問題不會阻止後續清理。
36. As an 工程師, I want 完整保存的輪次不再長期持有 writer 與不必要記憶體, so that App 可穩定長時間運作。
37. As an 工程師, I want 保存復原、封存及清理用相同的輪次狀態判定, so that 不會同時把同一輪判為未保存與可刪除。
38. As an 工程師, I want 新資料仍可用既有方式重建輪次且舊資料可讀, so that 部署新版本不破壞既有稽核查閱。

## Implementation Decisions

### 範圍與分工

- 本規格落實 ADR 0007／0008，並納入 P1 audit worker 生命週期作為保存模組的必要改善。平台解析快取等其他 P2 項目另案，不在本規格同時遷移。
- 沿用配置、平台資料來源、共同輪次與桌面介面的分工。共同輪次協調保存狀態、未保存輪次追蹤及封存條件；Session／audit writer 負責實際落盤與恢復；桌面介面呈現設定與操作。
- 以既有 RoundCoordinator 公開入口為主要行為測試邊界，擴充必要的保存狀態、重試、封存及清理控制；內部實作不要求 UI 接觸 store、queue 或 thread。清理功能收納於輪次紀錄生命週期模組，由同一協調入口管理，不另建各平台清理流程。

### 有序保存與復原

- audit writer 採約 0.2 秒空閒退出，有新工作再啟動。退出與新增工作協調，確保沒有工作停留於無 worker 的佇列；保留逐筆落盤及 flush 等待語意。排空不等於 worker 已退出，也不等於資料完整。
- 保留失敗工作及必要恢復資訊；同一紀錄串流在前筆失敗後不得形成可被誤判完整的序號缺口。重試沿用原事件序號、內容及操作時間，不以重試時間重造來源事實。
- 區分等待保存、保存中、保存失敗與完整保存等可觀察狀態；錯誤歷史與目前未保存狀態分開。恢復成功後可確認完整保存，歷史錯誤仍可追查。
- 完整保存涵蓋該輪所有必要 Session 與 audit 資料，包括最終結果、事件、來源 metadata、人工操作及輪次狀態；納入同步 enqueue／append 失敗、初始化與保存位置關聯失敗，不能僅依 worker 的錯誤旗標或 flush 回傳值。
- 寫入完成的確認須符合各紀錄既有落盤契約，恢復不能降低 audit 逐筆 fsync 的承諾。部分寫入、追加成功後回報失敗等情境以可驗證的紀錄身分及磁碟內容避免重複，重試過程不覆蓋其他輪次或有效紀錄。
- 停止收集後仍允許既有人工衝突處理及警報確認寫入；故障回報與重試本身不得形成無限遞迴的保存失敗事件。
- 本次執行的未保存輪次即使換輪仍受追蹤；確認完整保存後釋放不必要的物件與 worker。共享路徑鎖回收需保持同路徑互斥，不得因 worker 退出刪掉仍被使用的鎖。

### 正常關閉

- 關閉請求停止新增監控工作並處理正在進行的收集，於背景等待本次 App 執行期間所有未保存輪次，不以固定兩秒作為銷毀視窗的界線。
- 等待及重試時 Tk 事件迴圈持續運作，提供保存狀態、失敗原因、重試與取消關閉；反覆按鈕操作不建立並行關閉或重複重試。必要熱鍵及操作資源由關閉狀態管理，取消後不留下視窗存活但操作資源被永久關閉的狀態。
- 取消關閉保留未保存資料，不隱式重新開始已停止的來源收集。保存成功才走正常銷毀流程；沒有強制略過未保存資料的正常關閉選項。
- 關閉只追蹤本次執行的資料，不為此掃描全部歷史 Session。稽核失敗不額外阻擋產品結果放行，來源同輪判定與未知來源 FAIL 政策維持。

### 封存與保存設定

- 輪次結束、沒有待確認事項且所有必要紀錄完整保存後，持久記錄封存時間。停止讀檔、佇列排空、資料夾名稱或修改時間均不能單獨代替封存證據。
- 封存資料具有明確版本、輪次身分、封存時間及足以驗證相關保存資料完整的資訊，保留既有 audit／Session 讀取相容性。後續必要人工操作若尚未完成保存，不得沿用舊封存狀態批准刪除。
- 保存天數屬全域 App 設定，不屬單一測試配置；預設 365，只接受正整數，拒絕空白、非整數、零及負數。設定保存失敗呈現錯誤並維持原有效值；重啟、配置編輯及匯入匯出相關操作不得意外丟失此設定。
- 保存期限以封存時刻加設定天數計算；實作使用帶時區的持久時間及一致比較，天數按完整 24 小時定義，達到到期時刻即符合時間條件。來源測試時間與 App 封存時間是不同事實，不互相補造。
- 新期限套用全部可清理的既有紀錄，不只設定後的新輪次；縮短期限的提示需在設定畫面可見，實際刪除於下次背景清理發生。
- 歷史資料沒有可信封存資訊時保持可讀且保留；不從檔名、mtime 或測試時間猜測並補造封存時間。

### 背景清理

- 清理單位為同一輪次識別的整輪紀錄，涵蓋 audit、Session 事件、結果及 metadata；保存位置分散時聚合判定。任何組成部分不能確認完整性或所有權時保留。
- 清理資格同時要求：輪次已結束、無待確認事項、完整保存、可信封存資訊及超過期限；刪除前重新檢查，與保存及關閉狀態協調。
- 清理限 App 管理的輪次資料；不沿符號連結或外部參照刪除根目錄外資料，不碰配置、偏好、人工匯出及平台原始 Log。無法辨識、損壞、未完整保存或仍在使用的資料跳過。
- App 啟動後安排一次、持續開啟期間每 24 小時安排一次、有效保存天數修改後安排一次。多個觸發合併、不重疊，不在關閉保存期間啟動；已執行清理與關閉須安全協調，不阻塞 UI 或把正保存資料視為可刪。
- 背景逐輪處理，單輪失敗不使其他安全候選停止；留下清理摘要並於下次嘗試。多目錄部分刪除失敗須保留可恢復的進度資訊，下次不能把剩餘資料誤判為另一輪或已全部清理。
- 摘要持久記錄清理時間、當次保存天數、輪次識別、刪除／跳過／失敗結果與錯誤；不複製整輪內容，也不依賴已刪資料才能查閱。摘要寫入本身失敗必須可見，不得虛報清理成功。

### 交付順序

1. 修正 audit writer 空閒退出及相關資源生命週期。
2. 完成有序保存復原、跨輪次未保存追蹤與非阻塞正常關閉。
3. 完成封存契約、全域保存天數、背景清理與摘要。

每階段驗證既有行為及本階段必要故障案例、更新交付證據後提交並推送既有遠端，再推進下一階段。不以新增模組數或改善百分比作為驗收。

## Testing Decisions

- 使用者已確認：主要透過既有 RoundCoordinator 公開輪次入口、可注入時鐘、真實暫存檔及磁碟重建驗證保存／封存／清理；保留真正 Tk 測試驗證工程師設定、重試、取消關閉及視窗可操作性。
- 良好測試驗證可觀察行為、磁碟結果、重建結果與紀錄完整性，不依賴私有 queue 數量、特定 helper 呼叫次數或內部 thread 名稱。資源回收以多輪受控程序的 worker 成長與退出證據驗證。
- 沿用現有 audit 重建、fake clock 決定性輪詢、真實暫存來源、原子寫入故障、Session 背景保存及實際 Tk 圖形契約測試作法。新增需求可在同一高層協調入口控制時間與故障，不為每個平台建立新測試抽象。

### 必要驗收案例

1. 反覆多輪後 worker 不隨已結束輪次累積；空閒後再寫可重啟，退出與 enqueue 競爭不漏寫。
2. 停止讀檔後的衝突處理與警報確認仍保存，磁碟重建與原事件順序一致。
3. Session 或 audit 寫入失敗、部分寫入、追加後故障及同步 enqueue／append 失敗均不能被判為完整保存；修復重試後完整且沒有重複序號或事件。
4. 前輪保存失敗後開始新輪，關閉仍等待前輪；修復完成後釋放前輪的待保存資源。
5. 暫時與持續失敗均保持 UI 可操作；重試不重入，取消關閉保留資料，修復成功後歷史錯誤不永久阻止關閉。
6. 保存完整後才正常關閉；不得以測試中的 flush=True 掩蓋 audit_complete=False。產品結果放行及 KVM 顯示契約維持。
7. 預設 365、設定 180／其他正整數、拒絕無效值、重啟與其他配置保存後設定仍在；縮短期限提示可見。
8. 待確認數天後才完成保存，從實際封存時間起算；各測試使用注入時間，不等待真實天數。
9. 180／365 天期限之前、恰到期限與期限之後的清理結果明確；縮短設定使符合條件的舊輪次於下次清理到期。
10. 活躍、準備中、待確認、寫入中、保存失敗、未知、損壞及缺少可信封存時間的資料均保留。
11. 同輪早期 audit 與 Session 分散，仍按整輪判定；無法驗證任何組成部分時不清理。
12. 配置、偏好、人工匯出、原始來源及符號連結外部資料不被刪除。
13. 啟動、每日與設定修改觸發符合排程且不重疊；關閉保存期間不啟動新清理，既有工作安全協調。
14. 清理與保存競爭、單輪刪除失敗及多目錄部分失敗留下摘要，下次恢復而不誤刪保護資料。
15. 清理摘要在被刪輪次消失後仍可查閱；摘要寫入失敗可見。
16. 新舊 audit／Session 可讀，未到期或無可信封存時間資料的重建結果不受影響。

受控行為驗收及現有全套測試通過後才交付；真實 Tk 驗證使用可存取桌面圖形工作階段的環境。若環境限制使圖形或必要案例未執行，明記待驗，不能視為通過。量測不操作現場設備，不宣稱現場改善百分比。

## Out of Scope

- RS-WMT 解析快取、Session 來源 metadata 去重、B482 增量解析與 Atlas 搜尋優化另案。
- Tk 啟動組裝深模組重構、平台 observation／裁決型別及結果狀態集中遷移另案；P3 snapshot 優化不納入。
- 原始來源 Log、工程師配置、偏好、人工匯出與其他專案資料的自動刪除。
- 替舊資料猜測封存時間或自動宣告歷史損壞資料完整；關閉時掃描全部歷史 Session。
- 設定雲端備份、遠端同步、壓縮、備份復原或容量水位強制提早刪除未到期資料。
- 新增產品結果放行阻擋、改變未知同輪 FAIL 政策、KVM 契約、UI 技術或正式 macOS 建置 target。
- 強制終止程序、系統崩潰或斷電下的跨程序待保存工作恢復保證；本案正常關閉不得提供略過未保存資料的選項。
- 本次規格撰寫不包含產品實作、正式 bundle 建置、現場部署或目標設備驗收。

## Further Notes

- 政策依據為 ADR 0007「以封存時間管理整輪紀錄保存期限」、ADR 0008「完整保存本次執行的輪次資料後才關閉 App」；並維持 ADR 0004／0006。領域詞彙沿用「輪次紀錄」「封存時間」「待確認」。
- 封存與保存期限不取代寫入失敗復原；封存資格與結果可供上位機取用是不同條件。
- 正常關閉保存故障未排除時，App 保持開啟是已確認取捨；自動清理只刪除可信且已到期的資料，缺少封存資訊的歷史資料可能持續占用磁碟。
- 本規格建立於 2026-10-06（Asia/Taipei），當時只將已確認政策具體化為實作及驗收契約。後續各票的實作狀態與驗收證據分別記於票號索引及本機驗收紀錄；Ticket 07 的真正 Tk 與完整含 UI 套件已有通過證據，固定基準雙軸審查、覆蓋複核及整合尚待完成，因此不宣告全規格已完成。
