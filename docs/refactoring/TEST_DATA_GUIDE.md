## 三種驗證用途

1. **實機格式回歸**：以原始樣本的臨時副本驗證既有解析證據。預期結果須來自有依據的原始 final／可信欄位及既有保護基準，不能直接把待測程式輸出當作唯一答案。
2. **資料回放**：分步把副本放入臨時監控目錄，配合可控制日期及單調時鐘，驗證資料被觀察後的狀態、事件與停止條件。原始資料的完整檔案不證明實機逐步寫入的順序或速度。
3. **衍生模擬情境**：在副本或匿名化樣本上安排延遲、分段寫入、重複輸入、映射重排、空位、逾時或已確定同輪衝突。清楚標為合成情境，不冒充實機故障或實機容量證據。

需要容量 12／20、未放滿或異常分支時，可在已支援樣本語法及平台能力契約下產生受控資料；這只驗證共同輪次／布局，不代表四通道儀器實際支援二十片。全空、部分活動、COMPLETING 逾時、警報與衝突同時存在等，按正式規格及已確認測試接口驗證。

## 現有回放入口

在專案的 `B518 Log Solution` 程式目錄執行：

```zsh
python3 tools/replay_baseline_samples.py --caseinfo-date 2026-08-21 "/完整路徑/ATE Test doc"
```

將最後參數替換為實際資料根目錄。CaseInfo 有多個完整日期時須明確指定 `--caseinfo-date`；B518 BT 若增加多組候選資料夾，須另以 `--rswmt-run` 指定該資料夾名稱，不默認取最新或第一筆。

工具把選中輸入複製至臨時目錄，使用模擬時鐘，於回放前後比對原檔 SHA-256、大小及修改時間；摘要省略序號、來源路徑與 run 名稱。這個基準入口沿用現有監控器驗證解析保護；後續新版共同行為測試仍須使用已確認的輪次公開接口，不把此腳本當成四模組重構已完成的證明。

Ticket 01 已記錄先前回放：Atlas DFU 20 個 archive、FCT 7 個 archive；B482 7 組完整四通道／28 個結果（12 PASS、16 NOTEST），指定日期 CaseInfo 4 個通道；RS-WMT 4 個 Slot PASS。這是既有執行紀錄，本文件盤點沒有重新執行回放或新增測試通過紀錄。

Atlas 樣本只有 archive，既有回放以其副本模擬 active 觀察再讀 archive，不能當成真實 active tree 的實機驗收。B482 的群組選取以時間戳與結果分組，略過不完整或重複 Thread 群組；這是工具選樣規則，不能拿來決定未知同輪來源的採用政策。

## 可重現樣本與模擬規則

- 原件只讀；所有改寫、分段、檔名調整、延遲及新檔投遞都在臨時副本進行。不得把實機原件直接當可寫入監控工作目錄。
- 每個案例記錄來源集合／相對位置、資料版本或摘要校驗、平台、使用情境、選取日期／run、預期狀態，以及模擬時間與投遞步驟。含原始識別資訊的詳細清單保留本機；可分享版本使用匿名化識別。
- 需提交可重現樣本時，只取最小必要集合並匿名化；一致替換檔名與內容中的 SN／相關識別，保留位置、跨檔關係、編碼、換行及解析語法，並驗證匿名化前後語意等價。日期若須調整，所有相關時間證據與測試時鐘必須一致。
- 真實測試時間、檔案時間與複製時間分開；缺少來源時間或批次證據時保持未知，不因模擬而補成可信實機證據。
- 模擬正常資料和注入異常分開列出。結果衝突須明確標示同輪證據；未知是否同輪的案例可準備輸入，但採用／拒絕預期須等 Ticket 18 定案。
- 逐次記錄實際執行版本、工作目錄是否有相關未提交變更、環境、選樣參數、結果及限制。解析回放、Tk 畫面、目標 macOS／實機和上位機 KVM 組合驗收分開，不互相替代。
