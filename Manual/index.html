先認識畫面

主畫面功能導覽

主畫面是供 TE 查看結果與 KVM 擷取的固定看板。先設定路徑、再開始監控；它不會代替 Atlas 或 BT HMI 啟動測試。出現 PASS、FAIL 或 NOTEST 時，Log Solution 會自動回到前景，方便 KVM 讀取；TIMEOUT 與 STOPPED 不會觸發此動作。

標記區域／部件功能
1設定開啟「監控設定」與「事件與 Session」視窗，可選工站、設定路徑及逾時秒數、查看即時事件與開啟 Session 紀錄。
2版本與工站名稱顯示 B518 Log Solution 版本及目前監控的 DFU、FCT 或 BT 工站。
3監控狀態顯示待命、啟動中、監控中或逾時停止。待命表示目前沒有監控，畫面仍可能保留上一輪結果。
4KVM RESULT 色帶固定七格，左至右代表 Slot 1～7；兩端黑白標記用於定位及確認方向。DFU 使用 1～7、FCT 使用 1～6、BT 使用 1～4，其餘格固定黑色。
5KVM 狀態模板PASS、FAIL、TESTING、NOTEST 的固定顏色範本，供 KVM 先建立取樣模板；這四格不是操作按鈕。
6結果表格每個有效 Slot 顯示通道、目前狀態與產品 SN。BT 的 Slot 1～4 分別對應測試機 Thread 1～4。
7開始／停止監控「開始監控」會記錄本輪開始時間，並先記錄資料夾裡原本有哪些 Log，避免把舊結果當成這一輪的結果，可用 Command + Shift + M。開始不會啟動測試機；「停止監控」由人員結束本輪，尚未結束的通道改為 STOPPED，已完成的結果保留。

TE 操作指南

開始前確認

  • 已開啟 B518 Log Solution，且測試機將產生的 Log 資料夾可由此 Mac 讀取。
  • 畫面右上角的主看板不被 Atlas 或 BT HMI 覆蓋，供 KVM 擷取結果。
  • 每次新一輪測試前都要按「開始監控」；程式會記錄本輪開始時間及原有 Log；原本就存在且沒有更新的 CSV 不會當成本輪結果。

快速上手

  1. 開啟設定。在主畫面按「設定」。
  2. 選工站並設定路徑。選擇 DFU、FCT 或 BT，依下方說明按「選擇」挑選正確根目錄。
  3. 按儲存。工站、路徑和逾時值會一起保存；取消不會保存修改。
  4. 開始監控。按主畫面「開始監控」，或使用 Command + Shift + M。看到「啟動中」表示程式正在記錄資料夾裡原本有哪些 Log，避免把舊結果當成這一輪的結果；完成後會顯示「監控中」。
  5. 再開始操作測試機。等待監控進入「監控中」後才啟動測試。測試過程中確認 Slot 與 SN 是否正確。
  6. 讀取最終結果。待 PASS、FAIL、NOTEST 或 TIMEOUT 出現後，依「判讀結果」處置。下一輪請再次按開始監控。

逾時預設值：DFU 和 FCT 為等待開始 30 秒／測試上限 480 秒；BT 為 30 秒／240 秒。可在各工站設定中改成正整數秒數。

依圖 3 設定 BT 路徑並儲存

  1. 開啟設定。在主畫面按「設定」，確認目前在「監控設定」分頁。
  2. 選擇 BT 工站。在「工站」下拉選單選取 BT，畫面會顯示 BT TestData、BT CaseInfo 與兩個逾時欄位。
  3. 設定 TestData。在「BT TestData 根路徑」右側按「選擇」，選取 /vault/B482_RFTEST/TestData，再確認完整路徑已出現在欄位中。
  4. 設定 CaseInfo。在「BT CaseInfo 根路徑」右側按「選擇」，同樣選取 /vault/B482_RFTEST/TestData。此欄位可留空，但建議設定，讓測試進行時能提早顯示 SN 與 TESTING。
  5. 確認逾時秒數。BT 預設為等待開始測試逾時 30 秒、測試時間上限 240 秒；依產線需要調整時，兩個值都必須是正整數。
  6. 儲存設定。按右下角「儲存」，回到主畫面後才可按「開始監控」。按「取消」或直接關閉設定視窗都不會保存本次修改。

判讀結果

以下八種狀態與顏色已依目前 v0.1.0 原始碼核對；COMPLETING 為淺藍色。實機安裝包是否與此原始碼相同尚未驗證。

畫面狀態代表意義TE 下一步
WAITING本輪尚未看到此 Slot 的測試活動。確認先按開始監控，再確認測試機是否開始寫入正確路徑。
TESTING偵測到即時 Log 或 BT CaseInfo 活動；SN 可能已顯示。繼續等待最終結果，核對 Slot 與產品 SN。
COMPLETING等待最終測試結果，尚不代表測試通過。此狀態可能只短暫出現，畫面也可能直接由 TESTING 跳到 PASS／FAIL。等待 archive／TestData 寫入；若超過上限，依 TIMEOUT 處理。
PASS最終 Log 判定通過。依產線流程放行，必要時由 KVM 讀取色帶或畫面。
FAIL最終 Log 判定失敗，或 DFU/FCT 測試活動結束前未讀到可信 SN。依產線異常流程處理並保存原始 Log。
NOTESTDFU／FCT：本輪已有通道活動，且所有有效通道的 active 資料夾消失至少 3 秒後，未參與的通道由 WAITING 改為 NOTEST。BT：FAILED 最終 CSV 的 SN 為空時顯示 NOTEST。此狀態不表示整輪已完成。確認該 Slot 是否本來就未測；不是預期情況時回報。
TIMEOUT整輪等待開始逾時：期限內沒有任何通道活動或最終結果，所有有效 Slot 顯示 TIMEOUT 並停止監控。個別通道測試逾時：從首次活動起超過測試上限，只標記該 Slot，其餘未結束通道繼續監控。TIMEOUT 不代表產品 FAIL。檢查測試機、路徑與 Log；個別通道逾時時先保留其他通道的監控，整輪結束或手動停止後再開始新一輪。
STOPPED人員停止監控，尚未結束的通道改為 STOPPED，已完成的 PASS／FAIL／NOTEST 與已逾時的 TIMEOUT 保留。這不是產品 FAIL。若要繼續測試，重新開始一輪監控。

KVM 色帶與通道

頂端 KVM RESULT 永遠由左至右代表 Slot 1–7。DFU 使用 1–7、FCT 使用 1–6、BT 使用 1–4；不存在的通道固定為黑色。兩端黑白定位標記協助影像辨識確認方向。主畫面上的 PASS、FAIL、TESTING、NOTEST 色塊是 KVM 取樣模板，不是按鈕。

異常處理

無法開始監控／出現路徑錯誤

回到設定，確認必要欄位已選到根目錄、目錄仍存在且目前帳號有讀取權限。DFU/FCT 需要同時設定 active 與最終結果路徑；BT 必須設定 TestData，CaseInfo 可留空。

一直是 WAITING 或等待開始逾時

請確認按開始監控後才開始測試，並確認測試程式實際寫入所選路徑。程式會刻意忽略開始前就存在且未變更的檔案，以免舊結果被當成本輪結果。全輪沒有任何通道活動或最終結果，且達「等待開始測試逾時」時，所有有效 Slot 會變 TIMEOUT 並停止監控；排除原因後須重新開始監控。

顯示「SN 讀取失敗 / FAIL」

DFU/FCT 從 active 的 records.csv 讀可信 SN；若 active 消失前都未讀到可信 SN，會判 FAIL。請提供該 Slot 的 active records.csv 與最終結果 records.csv 給開發者。

個別 Slot TIMEOUT

從首次 TESTING／COMPLETING 起算，包含等待最終結果的時間；逾時只會標記該 Slot，其他未結束 Slot 繼續監控，已完成結果保留。先確認最終 CSV 是否遲到、寫在別的根目錄，或測試機本身停住。

BT 出現「人工覆核」

BT 會鎖定本輪第一個時間戳批次。若看到不同批次，或同一 Thread 出現另一個最終結果，程式會詢問是否接受新檔案。只有確認它屬於本輪、同一台機台要看的資料時才選「是」；不確定時選「否」並把 Session 和原始 Log 回報。

BT 為何先顯示 TESTING，再有 PASS／FAIL？

設定 CaseInfo 後，程式會讀取 Thread1–4 的 CaseInfo 活動並對應主畫面 Slot 1–4，可在最終 CSV 到達前顯示測試中與條碼。最終結果仍以 TestData 下的 PASSED／FAILED CSV 判定。
